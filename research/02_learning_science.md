# Learning science для Arvexo Arena

**Этап:** 2 из 8  
**Срез источников:** по 2026-07-20  
**Область решения:** обучение AI/ML школьников, студентов и начинающих взрослых в цифровой соревновательной среде  
**Статус:** исследовательская спецификация, не маркетинговое обещание

## 1. Итог одним абзацем

Arena не должна оптимизировать «пройденные экраны», streak, XP или результат сразу после урока. Наиболее надёжное ядро — короткое объяснение/разобранный пример для новичка, самостоятельное извлечение или решение, корректирующая обратная связь, повторное решение варианта, распределённые возвраты и затем новая задача на перенос без подсказок. Проекты, командная работа, AI-наставник и соревнование полезны только поверх этого контура и не являются сами по себе доказательством обучения. Навык считается освоенным лишь при устойчивом результате на параллельных формах, через 14/30 дней и на невиданной задаче; помощь, повтор вопросов и утечка шаблонов должны учитываться отдельно.

**Уверенность итогового решения:** высокая для разделения активности, assisted performance и самостоятельного обучения; средне-высокая для базового цикла retrieval → feedback → spaced return → transfer; средняя для конкретной комбинации методов в AI/ML; низкая для численных порогов, окон и ожидаемого effect size Arena до собственной валидации.

## 2. Как читать доказательства

### 2.1. Сила доказательств механизма

Это **method-level strength**, а не рейтинг надёжности отдельного источника. Для механизма используются значения `High / Moderate / Limited / Insufficient`; каждый источник отдельно получает ровно один рейтинг `A–D` по `00_research_plan.md`.

| Уровень | Что допускается | Как Arena использует вывод |
|---|---|---|
| **High** | Несколько качественных метаанализов/systematic reviews контролируемых исследований; образовательные полевые данные; результат — знание, удержание или перенос | Можно включать в базовый learning loop, но всё равно проверять локальным экспериментом |
| **Moderate** | Один хороший метаанализ, неоднородные обзоры либо несколько убедительных экспериментов; есть ограничения по предмету/возрасту | Вводить с feature flag, заранее заданной метрикой и анализом модераторов |
| **Limited** | Scoping/narrative review, малые или преимущественно наблюдательные исследования, узкий домен | Использовать как гипотезу дизайна, не как обещание результата |
| **Insufficient** | Правдоподобный механизм или framework без достаточной причинной проверки | Только пилот; нельзя заявлять эффективность |

Оценка относится не к модному названию, а к конкретной реализации и исходу. Например, для testing effect доказательность удержания знаний высокая, но для дальнего переноса на полноценный ML-проект — существенно ниже. Средний effect size из метаанализа не переносится на Arena как прогноз.

### 2.2. Правила причинных утверждений

1. Engagement, удовлетворённость, время в приложении и завершение курса — не learning outcomes.
2. Post-test сразу после практики смешивает обучение с кратковременной доступностью ответа.
3. Корреляция quiz score с экзаменом не доказывает эффект quiz: сильные ученики могут лучше делать и то и другое.
4. Собственные задания автора интервенции обычно ближе к обучению, чем независимые тесты, и могут завышать перенос.
5. Нельзя складывать средние эффекты разных методов: retrieval + spacing + feedback не означает сумму их `g`.
6. «AI-персонализация» — механизм доставки; её причинный эффект проверяется против неадаптивного, но равноценного по контенту и времени контроля.
7. Для несовершеннолетних дополнительно проверяются тревога, стигматизация, доступность, приватность и разрыв по исходной подготовке.
8. Все конкретные окна и пороги Arena (`T14/T30`, `0.90`, число попыток, интервалы между ними) — заранее заданные **design conventions**, а не научные константы. Они подлежат локальной валидации и пересмотру по стоимости false mastery/false non-mastery.

## 3. Карта методов: решение до деталей

| Метод | Сила для обучения | Главная граница | Роль в Arena |
|---|---:|---|---|
| active recall | High* | не всякий «ответ» требует извлечения | режим ответа до показа вариантов |
| retrieval practice | High* | перенос слабее прямого удержания | низкоставочные возвратные задания |
| spaced repetition | High для declarative retention; Moderate для AI/ML procedures | оптимальный интервал зависит от горизонта и материала | пилотный планировщик 1–3–7–14–30 с адаптацией |
| interleaving | Moderate | полезнее для различения похожих классов; может мешать новичку | смешанные диагностические наборы после базы |
| deliberate practice | Limited causal / Moderate association | доступная база в основном корреляционная; нужен экспертный feedback | тренировка конкретной слабой микрокомпетенции |
| mastery learning | Moderate | больше времени; self-paced может снижать completion | шлюз по независимым evidence, не по числу попыток |
| competency-based learning | Limited | неодинаковые определения и слабая причинная база | прозрачный граф компетенций и артефактов |
| project-based learning | Moderate | сильная неоднородность; риск неравного вклада | ограниченный проект после prerequisite checks |
| problem-based learning | Moderate | знание фактов может уступать прямому обучению | кейс → попытка → инструкция → новый кейс |
| challenge-based learning | Limited | термин не стандартизован, причинных данных мало | внешний brief только в пилоте |
| inquiry-based learning | Moderate | направляемое inquiry лучше минимального guidance | исследование датасета с поэтапными опорами |
| peer learning | Moderate | качество партнёра и объяснения критично | проверяемое взаимное объяснение |
| collaborative learning | Moderate | social loafing и group score скрывают индивида | роли + индивидуальный контроль переноса |
| formative assessment | Moderate | ярлыком называют очень разные циклы | evidence → diagnosis → action → reassessment |
| immediate feedback | Moderate для timing | может быть полезнее для нового/сложного, но создать зависимость | мгновенная проверка безопасности/синтаксиса |
| delayed feedback | Moderate | не универсально лучше; зависит от задачи | разбор стратегии после завершённой попытки |
| worked examples | Moderate | expertise reversal | пример с решениями для новичка, затем completion |
| scaffolding | Moderate | помощь может стать постоянной | минимально достаточная ступенчатая подсказка |
| fading | Moderate | нет универсального расписания снятия опор | снятие по независимому успеху, не по времени |
| cognitive load theory | Moderate | теория развивается; субъективная нагрузка шумна | убрать split attention и лишний интерфейс |
| desirable difficulties | Moderate | трудность полезна только если достижима и улучшает delayed outcome | калиброванное усилие с recovery path |
| generation effect | Moderate | неверная генерация без коррекции закрепляет ошибку | гипотеза/код до показа решения |
| testing effect | High* | teaching-to-test и тревога при high stakes | частые low-stakes quizzes с feedback |
| self-explanation | Moderate | качество объяснения, не длина текста, создаёт эффект | «почему этот split валиден?» по рубрике |
| metacognition | Moderate | self-report и уверенность сами по себе ненадёжны | прогноз уверенности + calibration feedback |
| reflection | Limited | шаблонные дневники легко имитировать | короткий error/action log, проверяемый следующей задачей |
| transfer | Insufficient как intervention; strength неприменима к обязательному исходу | far transfer редок и неоднозначно определяется | невиданные контексты и независимые артефакты |
| adaptive learning | Moderate | ITS ≠ любой recommender; возможен widening gap | адаптация следующего evidence, не упрощение стандарта |
| microlearning | Limited | формат длительности, не механизм памяти | короткие единицы внутри длинного цикла практики |
| productive failure | Moderate | работает при fidelity: подготовительная задача + консолидация | сначала ограниченная попытка, затем сравнение решений |
| error-based learning | Moderate | ошибки полезны только с коррекцией; не всем группам одинаково | персональный error family replay |
| learning by teaching | Moderate | большинство исследований со взрослыми; интерактивность важна | объяснение peer/teachable agent + вопросы |

`*` Active recall, retrieval practice и testing effect разделены для терминологической полноты, но используют одну evidence family. Это не три независимых эффекта, их нельзя складывать или считать тремя отдельными подтверждениями механики.

## 4. Подробные карточки методов

### 4.1. Извлечение, тестирование и распределение

#### M01 — Active recall / активное воспроизведение

- **Определение.** Намеренная попытка воспроизвести ответ, процедуру или объяснение из памяти *до* повторного просмотра. Термин в практике часто используется как синоним retrieval practice, но здесь обозначает интерфейсное действие ученика.
- **Доказательства.** **High** для удержания изученного материала как конкретной реализации retrieval/testing; не существует отдельного корпуса, позволяющего приписать «active recall» иной эффект. IES/WWC рекомендует active retrieval в quizzes; Yang et al. объединили 48 478 учеников из 222 classroom studies и получили средний `g=0.499`, при существенной неоднородности [ES-L01, ES-L04].
- **Ограничения/противоречия.** Узнавание варианта ответа может требовать мало извлечения. Выигрыш для непроверенного материала меньше, чем для проверенного; совпадение формата practice/final test повышает результат, поэтому часть эффекта может быть format-specific.
- **Кому подходит.** После первого кодирования понятия — школьники, студенты, взрослые; свободный ответ требует больше поддержки у новичка и при языковых барьерах.
- **Ошибка внедрения.** Показать варианты или правильный код до попытки; засчитать перечитывание flashcard как recall; делать упражнение оценочным и тревожным.
- **AI/ML и Arena mechanic.** Перед вариантами ученик пишет: «какую утечку здесь видишь и почему?» или восстанавливает 3 строки preprocessing pipeline. После commit показываются варианты/рубрика.
- **Проверочная метрика.** `unaided_recall@14d`: доля ключевых элементов рубрики, воспроизведённых без options/hints на параллельной форме через 14 дней.
- **Возможный negative effect.** Повторное воспроизведение уверенной ошибки без быстрой коррекции усиливает misconception; high-stakes оформление повышает тревогу и avoidance.

#### M02 — Retrieval practice / практика извлечения

- **Определение.** Серия событий, где ученик извлекает знание или процедуру из памяти, получает корректирующую информацию и позже снова извлекает её; это шире одной карточки active recall.
- **Доказательства.** **High** для удержания. Rowland meta-analysis сравнил testing с restudy и показал зависимость эффекта от успешности и формата извлечения; systematic review 50 classroom experiments Agarwal et al. обнаружил пользу в разных уровнях и предметах, но только 6% экспериментов были вне WEIRD-стран [ES-L02, ES-L03].
- **Ограничения/противоречия.** Неуспешное извлечение без feedback может не помочь; эффект на authentic transfer не гарантирован. Контроль restudy слабее, чем равноценная активная практика.
- **Кому подходит.** Всем после минимального знакомства; для очень слабого ученика — cue → partial completion → free recall.
- **Ошибка внедрения.** Повторять один item, считать краткосрочную точность обучением, не балансировать exposure между группами.
- **AI/ML и Arena mechanic.** Возвратная миссия: на новом датасете выбрать split, метрику и baseline, затем объяснить решения без открытой теории; corrective feedback связывается с конкретной misconception.
- **Проверочная метрика.** Иерархическая модель вероятности правильного независимого ответа по skill с контролем исходного уровня, количества exposures и item difficulty; основной endpoint — odds/gain на delayed parallel items.
- **Возможный negative effect.** «Drill» по поверхностным вопросам оптимизирует узнавание терминов и вытесняет проектную практику; повтор неправильного distractor создаёт familiarity.

#### M03 — Testing effect / эффект тестирования

- **Определение.** Более долговременное запоминание после теста/quiz, который сам служит учебным событием, по сравнению с повторным изучением; это наблюдаемый эффект, а retrieval practice — педагогический процесс.
- **Доказательства.** **High**. Yang et al.: 573 эффекта, 222 независимых classroom studies, `g=0.499 [0.442; 0.557]`; 82.9% эффектов положительные, но гетерогенность значительна. Feedback усиливал средний эффект (`g=0.537` против `0.374` без него); эффект для непроверенного знания был меньше (`g=0.321` против `0.512` для проверенного) [ES-L04].
- **Ограничения/противоречия.** Эти числа — описательная агрегация неодинаковых дизайнов, не прогноз Arena. Format match (`g=0.531`) против mismatch (`g=0.399`) указывает и на transfer-appropriate processing. Частые тесты могут перераспределить study time.
- **Кому подходит.** Low-stakes форматы от начальной школы до вузов; письменное объяснение и coding tasks — после соответствующей подготовки.
- **Ошибка внедрения.** Использовать leaderboard/high stakes, один и тот же банк, давать балл за угадывание, публиковать `g=0.499` как обещание продукта.
- **AI/ML и Arena mechanic.** «Retrieval checkpoints» без рейтингового штрафа: термин → выбор решения → короткое обоснование → feedback → variant retry; рейтинговый турнир использует отдельный, закрытый банк.
- **Проверочная метрика.** ITT-оценка через ANCOVA или item-level mixed model с baseline и assignment condition; отдельно tested, structurally similar и unseen-transfer items. Если используется randomized encouragement, complier effect оценивается отдельно от ITT.
- **Возможный negative effect.** Teaching-to-test, test anxiety, игровая эксплуатация банка вопросов и ложное mastery по знакомым items.

#### M04 — Spaced repetition / распределённое повторение

- **Определение.** Повторные учебные/извлекающие события разделены интервалами, а не собраны в один massed session; scheduling — отдельная переменная от retrieval.
- **Доказательства.** **High** для долговременного запоминания изученного материала; **Moderate** для процедурной практики и переноса в AI/ML, где база уже. Cepeda et al. синтезировали 839 оценок из 317 экспериментов; оптимальный lag связан с требуемым retention interval. Dunlosky et al. оценили distributed practice как high utility; WWC — moderate evidence [ES-L05, ES-L06, ES-L01].
- **Ограничения/противоречия.** Единого интервала «1–3–7» наука не устанавливает. Много исследований — простые verbal materials. Systematic review Chen et al. подчёркивает: spacing и interleaving имеют разные определения/предполагаемые механизмы [ES-L07].
- **Кому подходит.** Всем; особенно долговременные основы (метрики, leakage, overfitting, SQL/Python syntax), но не заменяет цельную проектную работу.
- **Ошибка внедрения.** Фиксированный календарь для всех, повтор узнаваемых карточек, обнуление streak за пропуск, смешение spacing и microlearning.
- **AI/ML и Arena mechanic.** Scheduler прогнозирует next-review window из target horizon, difficulty и независимой recall history; каждый возврат меняет данные/формулировку и постепенно убирает cues.
- **Проверочная метрика.** Area under retention curve по 1/7/14/30 дням; secondary — число попыток/минут до критерия и calibration. Сравнивать с massed/простым fixed schedule при равном времени.
- **Возможный negative effect.** Review debt и уведомления превращают продукт в chore; слишком ранний повтор создаёт иллюзию лёгкости, слишком поздний — фрустрацию и dropout.

#### M05 — Interleaving / чередование

- **Определение.** Практика разных, обычно похожих, типов задач в смешанной последовательности вместо блоков `AAA BBB`; ключевой навык — распознать, *какой* метод нужен.
- **Доказательства.** **Moderate**. Brunmair & Richter meta-analysis показал положительный средний эффект с сильными модераторами и особой пользой для категориального/визуального различения; для части математических материалов эффект слабее или отрицателен. Chen et al. systematic review различает 48 spacing и 67 interleaving studies и поддерживает discriminative-contrast как отдельное объяснение [ES-L08, ES-L07].
- **Ограничения/противоречия.** Слишком несходные темы не создают полезного контраста; новичку до формирования схем блок может быть эффективнее. Чередование автоматически добавляет spacing, что осложняет причинную атрибуцию.
- **Кому подходит.** После базового blocked acquisition; особенно ученикам, которые умеют выполнить алгоритм после подсказки, но не выбирают его сами.
- **Ошибка внедрения.** Случайная мешанина уровней; interleave до первого успешного примера; смешивать только контент, не требуя выбора стратегии.
- **AI/ML и Arena mechanic.** Mixed set: leakage, imbalance, drift, overfit и wrong metric выглядят похожими; ученик сначала классифицирует проблему, затем чинит pipeline.
- **Проверочная метрика.** Accuracy выбора метода на новых близких distractor cases и discrimination index; перенос на blocked-trained vs interleaved-trained при равных exposures.
- **Возможный negative effect.** Резкое падение текущей performance воспринимается как регресс; избыточная интерференция закрепляет неверные границы категорий.

### 4.2. Достижение мастерства и направленная практика

#### M06 — Deliberate practice / целенаправленная практика

- **Определение.** Структурированная работа над конкретной слабостью за пределами текущей лёгкости, с ясным представлением качественного выполнения, информативным feedback и повторной коррекцией; не синоним «много часов практики».
- **Доказательства.** **Limited** для причинного эффекта; **Moderate** для ассоциации и границ конструкта. Классическая работа Ericsson, Krampe & Tesch-Römer формализовала подход на музыкантах; correlational meta-analysis Macnamara et al., с учётом corrigendum 2018, обнаружил, что deliberate practice объясняла различную долю вариации по доменам и около **5%** в education (общая оценка исправлена с 12% до 14%). Это не treatment effect и не доказывает, что назначение практики вызовет такой прирост; работа опровергает лишь универсальную «10 000 часов» формулу [ES-L09, ES-L10].
- **Ограничения/противоречия.** Самоотчёт практики, reverse causality, отбор способных/обеспеченных участников; спор о строгом определении. Практика — один фактор среди prior knowledge, instruction, opportunity и мотивации.
- **Кому подходит.** Ученик уже понимает цель и имеет стабильный baseline; новичку нужна инструкция/пример до самостоятельной deliberate practice.
- **Ошибка внедрения.** Назвать любой grind deliberate; увеличивать difficulty без diagnosis; feedback «неверно» без следующего действия.
- **AI/ML и Arena mechanic.** Skill clinic строит 5 вариаций одной подтверждённой ошибки (например, leakage при preprocessing), показывает expert contrast и заканчивается независимым variant.
- **Проверочная метрика.** Learning slope на *новых* items семейства плюс снижение error recurrence через 14 дней; time-on-task не является успехом.
- **Возможный negative effect.** Узкая сверхспециализация, fatigue, отказ из-за постоянной работы по слабостям; алгоритм может ошибочно зафиксировать ученика в remedial loop.

#### M07 — Mastery learning / обучение до освоения

- **Определение.** Цели разбиты на единицы; после формативной проверки ученик получает корректирующее обучение и новые попытки, переходя дальше после заранее заданного критерия, при варьируемом времени.
- **Доказательства.** **Moderate**, но большая часть базы стара. Meta-analysis Kulik, Kulik & Bangert-Drowns включил 108 controlled evaluations: положительные экзаменационные результаты, сильнее для слабых учеников; одновременно больше времени, а self-paced mastery в вузах нередко снижал completion [ES-L11].
- **Ограничения/противоречия.** Criterion часто измерялся близким авторским тестом; «mastery» пороги различаются; повтор одного теста смешивает знание с item memory. Эффект пакета не идентифицирует вклад порога, feedback или extra time.
- **Кому подходит.** Последовательные prerequisites: data split до validation, Python basics до pipeline, metrics до model selection.
- **Ошибка внедрения.** Порог 80% по тем же вопросам; бесконечная пересдача; заблокировать весь путь из-за одной микродетали; игнорировать скорость/стоимость.
- **AI/ML и Arena mechanic.** Gate открывается при двух успешных параллельных формах в разные дни, минимум одной без hints и отсутствии критической ошибки; corrective branch короткий и заканчивается novel check.
- **Проверочная метрика.** Mastery — явная conjunction независимого model evidence, покрытия item families, минимального elapsed lag, delayed evidence, переноса и отсутствия unresolved critical error по §6.7, а не произведение несопоставимых величин и не best score. Completion/time cost и differential progression обязательны рядом с learning outcome.
- **Возможный negative effect.** Медленный ученик застревает и стигматизируется; быстрый скучает; self-paced путь увеличивает dropout без deadline/support.

#### M08 — Competency-based learning / компетентностное обучение

- **Определение.** Организация программы вокруг наблюдаемых результатов деятельности и критериев их демонстрации, а не времени в курсе; компетенция объединяет знание, решение и контекст применения.
- **Доказательства.** **Limited** как целостной реформы. Systematic review Evans et al. по K–12 (2000–2019) нашёл лишь 12 outcome studies и подчёркивает неодинаковые определения и невозможность отделить CBE от дифференциации/поддержки; umbrella review 2025 также фиксирует преобладание обзоров и health/higher-ed контекстов [ES-L12, ES-L13].
- **Ограничения/противоречия.** CBE — архитектура измерения, не единая intervention. Декомпозиция может атомизировать сложную работу; локальные рубрики имеют слабую переносимость и межэкспертную надёжность.
- **Кому подходит.** Портфельная AI/ML траектория школьник→стажёр, если компетенции понятны ученику, родителю и эксперту.
- **Ошибка внедрения.** Badge за activity; сотни микроскиллов без интеграции; self-report как доказательство; менять rubric после выполнения без versioning.
- **AI/ML и Arena mechanic.** Versioned competency graph: evidence links к quiz, unseen case, code artifact, explanation и project review; у каждого evidence — task/version, help level, reviewer и срок давности.
- **Проверочная метрика.** Межэкспертная согласованность rubric, predictive validity следующей независимой задачи, доля компетенций с ≥2 типами evidence и false-mastery audit rate.
- **Возможный negative effect.** «Геймификация чекбоксов», credential inflation, чрезмерное слежение и барьеры для нестандартных, но качественных решений.

### 4.3. Проект, проблема, вызов и исследование — четыре разных семейства

#### M09 — Project-based learning / проектное обучение

- **Определение.** Продолжительная работа над осмысленным вопросом с созданием публично проверяемого продукта; проект организует обучение, а не служит красивым заданием в конце лекции.
- **Доказательства.** **Moderate**. Chen & Yang meta-analysis: 30 статей, 46 сравнений, 12 585 учеников, положительный средний эффект, но существенная зависимость от предмета, длительности и дизайна. Более новый synthesis 66 experimental/quasi-experimental papers и 190 effects также обнаружил сильные модераторы: регион, предмет, возраст, размер группы/класса и длительность [ES-L14, ES-L15].
- **Ограничения/противоречия.** Publication bias, неодинаковые определения PjBL, авторские outcome tests и квазиэксперименты; средний эффект не доказывает дальний перенос или employability. Project-based нельзя смешивать с problem-based.
- **Кому подходит.** После освоения минимальных prerequisites; учащимся, способным планировать несколько сессий. Младшим и новичкам нужны milestones, примеры и роли.
- **Ошибка внедрения.** «Сделайте AI-приложение» без данных/критериев; оценивать polish вместо корректности; один участник делает код; дать проект раньше основы.
- **AI/ML и Arena mechanic.** 2–4-недельный проект из versioned brief: data card → baseline → validation → error analysis → model card/demo. Milestone требует индивидуального defense fragment.
- **Проверочная метрика.** Blind rubric по корректности split, baseline, reproducibility, error analysis и limitations; индивидуальный unseen transfer после проекта; межэкспертная надёжность.
- **Возможный negative effect.** Неравенство по времени/устройствам/помощи взрослых, social loafing, «работающий demo» с утечкой и иллюзия mastery у пассажира команды.

#### M10 — Problem-based learning / проблемно-ориентированное обучение

- **Определение.** Обучение начинается с сложной проблемы; учащиеся выявляют, чего не знают, изучают необходимое и возвращаются к решению. Конечный продукт необязателен; это отличает метод от PjBL.
- **Доказательства.** **Moderate**, неоднозначные по типу исхода. Meta-synthesis Strobel & van Barneveld сообщает преимущества PBL для долгого удержания, skills и удовлетворённости, тогда как conventional instruction часто лучше на краткосрочном знании/standardized tests. Systematic review medical education указывал на слабое/возможное отрицательное evidence для possession of knowledge, но лучшее применение знания [ES-L16, ES-L17].
- **Ограничения/противоречия.** Большая доля данных из medicine; PBL-пакеты меняют сразу curriculum, collaboration, tutor time и assessment. Минимально направляемое problem solving перегружает новичков.
- **Кому подходит.** Intermediate learners или новички после короткого schema-building блока и с facilitator prompts.
- **Ошибка внедрения.** Равнять PBL свободному discovery; не дать консолидации правильной модели; оценивать только командный ответ.
- **AI/ML и Arena mechanic.** Кейс: «offline accuracy растёт, production жалобы тоже». Ученик формулирует hypotheses/evidence needs; Arena выдаёт данные по запросу; после решения — canonical comparison и новый кейс.
- **Проверочная метрика.** Качество problem representation, число диагностически ценных запросов, корректность следующего невиданного кейса и сохранение core knowledge через 14 дней.
- **Возможный negative effect.** Закрепление фрагментарной/ошибочной модели, чрезмерное время, доминирование сильного участника и потеря базовых знаний.

#### M11 — Challenge-based learning / обучение через вызов

- **Определение.** Учащиеся формулируют или принимают открытый общественный/индустриальный вызов, исследуют stakeholders, создают и внедряют решение. Обычно добавляет real-world partner и действие, чего может не быть в PBL/PjBL.
- **Доказательства.** **Limited**. Gallagher & Savage exploratory review выявил множество несовместимых frameworks; systematic review Leijon et al. по higher education отметил слабую или отсутствующую научно-теоретическую основу многих публикаций. Evidence чаще про опыт/engagement, не причинный learning gain [ES-L18, ES-L19].
- **Ограничения/противоречия.** Сильный selection bias, локальные кейсы, self-report, отсутствие контроля и стандартизации; термин часто ребрендирует project/problem learning.
- **Кому подходит.** Старшие школьники, студенты и команды с наставником, после базового курса; не default для одиночного новичка.
- **Ошибка внедрения.** Реальный партнёр без безопасного sandbox; обещать impact; оценивать презентацию; использовать чувствительные данные несовершеннолетних.
- **AI/ML и Arena mechanic.** Пилотный partner brief с синтетическими/обезличенными данными и независимой ethical review; challenge decomposed на research, prototype, limitations и defense.
- **Проверочная метрика.** До/после parallel assessment + blind artifact rubric + stakeholder utility отдельно; никаких выводов по NPS/attendance.
- **Возможный negative effect.** Эксплуатация бесплатного труда, эмоциональная/репутационная цена неудачи, privacy risk, вознаграждение «эффектной» истории вместо корректного ML.

#### M12 — Inquiry-based learning / исследовательское обучение

- **Определение.** Ученик задаёт вопрос/гипотезу, собирает и интерпретирует evidence, строит и пересматривает объяснение. Степень guidance варьируется; guided inquiry не равно unguided discovery.
- **Доказательства.** **Moderate**. Furtak et al. meta-analysis experimental/quasi-experimental science studies оценил положительный средний эффект; Lazonder & Harmsen meta-analysis показал пользу guidance и для content knowledge, и inquiry skill. Свободное discovery без guidance заметно слабее направляемых форм [ES-L20, ES-L21].
- **Ограничения/противоречия.** Преимущественно science education, разные контроли и outcome measures. Эффект guided inquiry нельзя использовать как подтверждение «учитель не нужен».
- **Кому подходит.** После базовой схемы; уровень guidance выше для младших, слабой prior knowledge и сложного инструментария.
- **Ошибка внедрения.** Дать notebook и сказать «найдите insight»; не проверить качество данных/множественные сравнения; подсказать вывод вместо процесса.
- **AI/ML и Arena mechanic.** Guided data investigation: вопрос → preregistered hypothesis → выбор plot/test → evidence → альтернативное объяснение; hints указывают на процесс, а не ответ.
- **Проверочная метрика.** Rubric качества гипотезы, evidence–claim alignment, контроля leakage/confounds и пересмотра вывода на counterexample dataset.
- **Возможный negative effect.** P-hacking, confirmation bias, extraneous tool load и формирование уверенных выводов из шума.

### 4.4. Социальное обучение

#### M13 — Peer learning / обучение со сверстником

- **Определение.** Учащийся учится через объяснение, взаимную проверку, tutoring или feedback от равного/почти равного по статусу участника. Это не просто совместное присутствие.
- **Доказательства.** **Moderate**. Meta-analysis single-case research Bowman-Perrott et al. поддерживает academic benefits peer tutoring в K–12, включая учащихся с disability; корпус неоднороден и не охватывает все digital peer-review форматы [ES-L22].
- **Ограничения/противоречия.** Peer может передать misconception; дружба/статус, язык и prior knowledge влияют на взаимодействие. Не вся peer оценка надёжна.
- **Кому подходит.** Пары с близкой зоной сложности и явным rubric; младшим нужна модерация и безопасные шаблоны общения.
- **Ошибка внедрения.** Случайное pairing без opt-out; «оцените от 1 до 5»; вознаграждать согласие; раскрывать личные слабости публично.
- **AI/ML и Arena mechanic.** Каждый получает анонимизированный model card партнёра: отметить один риск, запросить evidence, предложить test. Автор обязан принять/отклонить с обоснованием; system проверяет rubric anchors.
- **Проверочная метрика.** Точность peer comments против expert sample, revision quality, индивидуальный transfer обеих сторон и harm/moderation rate.
- **Возможный negative effect.** Дезинформация, harassment, статусная и гендерная асимметрия, копирование решения и зависимость от более сильного ученика.

#### M14 — Collaborative learning / совместное обучение

- **Определение.** Совместное построение решения с позитивной взаимозависимостью и индивидуальной ответственностью; cooperative structures обычно жёстче задают роли, collaborative — оставляют больше самоуправления.
- **Доказательства.** **Moderate**. Kyndt et al. meta-analysis современных face-to-face studies обнаружил положительные эффекты на achievement и attitudes, но значительную гетерогенность и зависимость от структуры [ES-L23].
- **Ограничения/противоречия.** Групповая оценка не идентифицирует индивидуальное обучение; контекст face-to-face не автоматически переносится online. Состав группы — сильный модератор.
- **Кому подходит.** Задачи с реально делимыми, но интегрируемыми перспективами: data, modelling, evaluation, ethics; не искусственное деление короткого quiz.
- **Ошибка внедрения.** Одна общая submission; роли без ротации; leaderboard команд без readiness bands; чат вместо совместного reasoning.
- **AI/ML и Arena mechanic.** Роли Data Steward, Modeller, Evaluator, Red Teamer с раздельными actions/logs; перед merge каждый проходит cross-role question, после — индивидуальный unseen case.
- **Проверочная метрика.** Индивидуальный gain, равномерность вкладов (не как цель, а audit), cross-role knowledge, quality интеграции и доля команд с пассажирами.
- **Возможный negative effect.** Social loafing, доминирование, координационная нагрузка, наказание сильного участника и сокрытие пробелов слабого.

### 4.5. Формативный цикл и время обратной связи

#### M15 — Formative assessment / формативное оценивание

- **Определение.** Не «частый тест», а цикл: получить evidence текущего понимания → интерпретировать относительно цели → изменить следующее действие ученика/системы → повторно проверить.
- **Доказательства.** **Moderate**. Kingston & Nash просмотрели >300 K–12 studies и показали, что популярное утверждение об effect size `0.40–0.70` не поддерживается качеством исходной базы; их оценки различались по предметам. Это поддерживает механизм, но требует осторожности с величиной [ES-L24].
- **Ограничения/противоречия.** «Formative assessment» включает несовместимые interventions; слабая randomization и author-made measures. Тест без action не формативен.
- **Кому подходит.** Все уровни, если action реально доступен: другой пример, объяснение, tutor escalation, пауза или advancement.
- **Ошибка внедрения.** Dashboard для учителя без решения; feedback через неделю после закрытия темы; ставить grade и вызывать defensiveness; собирать telemetry без пользы ученику.
- **AI/ML и Arena mechanic.** Evidence event обновляет misconception tag, но не «понижает человека»; система предлагает одну обоснованную next action и позже проверяет именно её результат.
- **Проверочная метрика.** `actionability rate` (доля evidence, приведшая к релевантному действию), gain на reassessment и false-diagnosis audit; click-through не считается learning.
- **Возможный negative effect.** Over-testing, surveillance, алгоритмический tracking в «слабую» ветку и сужение curriculum до измеряемого.

#### M16 — Immediate feedback / немедленная обратная связь

- **Определение.** Корректирующая информация во время или сразу после ответа/шага; может сообщать correctness, место ошибки, принцип и следующее действие.
- **Доказательства.** **Moderate** для timing; общая польза содержательного task-level feedback имеет более сильную базу, но не определяет момент выдачи. Meta-analysis Kulik & Kulik 53 studies: в applied classroom quizzes/реальных материалах immediate чаще лучше, тогда как laboratory test-content иногда выигрывал от delay. Shute review рекомендует immediate для сложной новой задачи, но подчёркивает зависимость от learner, task и outcome [ES-L25, ES-L26].
- **Ограничения/противоречия.** Мгновенный показ полного решения меняет задачу на чтение. Effects разных содержаний feedback нельзя сводить к одному timing.
- **Кому подходит.** Новичок, синтаксическая/безопасностная ошибка, шаг с риском накопления неверной процедуры.
- **Ошибка внедрения.** Красный крест без объяснения; auto-complete до попытки; interrupt каждый шаг; praise личности вместо task/process info.
- **AI/ML и Arena mechanic.** Сразу блокировать data leakage/невоспроизводимую операцию с указанием нарушенного инварианта; сначала дать минимальный cue, полный worked step — по запросу с учётом help level.
- **Проверочная метрика.** Corrected-on-next-independent-attempt, time-to-recovery и help dependency; не доля закрытых tooltips.
- **Возможный negative effect.** Feedback dependency, trial-and-error clicking, прерывание productive reasoning и снижение самоконтроля.

#### M17 — Delayed feedback / отложенная обратная связь

- **Определение.** Корректирующая информация после законченной попытки, блока или временного интервала, чтобы ученик сначала сохранил/восстановил собственную модель решения.
- **Доказательства.** **Moderate**, не универсальная победа. Butler, Karpicke & Roediger experiments нашли преимущество delayed feedback на последующем тесте; Mullet et al. в двух экспериментах upper-level engineering course обнаружили лучший exam transfer при недельной задержке, несмотря на предпочтение immediate. Старый meta-analysis даёт обратный вывод для многих applied tasks [ES-L27, ES-L28, ES-L25].
- **Ограничения/противоречия.** «Delay» — от конца item до недели; эффекты зависят от сложности, памяти ответа и наличия intervening study. Один вузовский курс не переносится на школьника.
- **Кому подходит.** Относительно освоенная стратегия, целостный reasoning/проектный фрагмент; не критическая ошибка новичка.
- **Ошибка внедрения.** Откладывать correctness настолько, что ученик забудет контекст; смешать delayed feedback со spaced reattempt; не сохранить исходный ответ.
- **AI/ML и Arena mechanic.** Во время целостной model-selection попытки Arena фиксирует reasoning без вмешательства, а после commit/end-of-attempt показывает contrastive audit — это **end-of-attempt feedback**, не многосуточная задержка. Новый dataset через пилотное окно 24–72 часа — отдельный **spaced reattempt**, не evidence delayed feedback. Если Arena проверяет именно временную задержку feedback, тот же audit рандомизируется к заранее заданному delay при неизменных content и reattempt schedule.
- **Проверочная метрика.** Unseen transfer и retention при randomized immediate vs end-of-block/delayed feedback, с равным содержанием; добавить preference отдельно.
- **Возможный negative effect.** Фрустрация, закрепление опасного процесса и невозможность исправить downstream steps; пользователь считает систему «молчащей».

#### M18 — Feedback как информационный дизайн (связующая карточка)

- **Определение.** Информация, уменьшающая разрыв между текущим и целевым выполнением: где ошибка, какой принцип нарушен, что проверить следующим. Timing сам по себе недостаточен.
- **Доказательства.** **Moderate**. Wisniewski, Zierer & Hattie meta-analysis 435 studies, 994 effects, `N>61 000`: средний `d=0.48`, высокая неоднородность и сильная зависимость от информационного содержания. Kluger & DeNisi historical meta-analysis: более 38% effects были отрицательными, особенно когда внимание смещалось к self, а не task [ES-L29, ES-L30].
- **Ограничения/противоречия.** Среднее смешивает разные outcome/domain/control; часть классических studies не образовательная. Нельзя ранжировать продукт по одному агрегату.
- **Кому подходит.** Всем при адаптации языка, детализации и agency.
- **Ошибка внедрения.** «Молодец/плохо», personality labels, десять советов сразу, feedback без retry, LLM-оценка без grounded rubric.
- **AI/ML и Arena mechanic.** Формат `наблюдение → нарушенный критерий → минимальный контрпример → следующий тест`; генеративный текст только из validated rule/evidence, с uncertainty/escalation.
- **Проверочная метрика.** Доля feedback, после которого исправлен принцип на новом случае; expert factuality audit, overhelp rate, subgroup harm.
- **Возможный negative effect.** Удар по самоэффективности, информационная перегрузка, принятие ошибочного AI feedback и оптимизация под rubric вместо смысла.

### 4.6. Поддержка новичка и управление сложностью

#### M19 — Worked examples / разобранные примеры

- **Определение.** Полное решение задачи с явными промежуточными решениями и основаниями, которое ученик изучает до/вместо самостоятельного решения; особенно снижает бесплодный search у новичка.
- **Доказательства.** **Moderate**. Review Atkinson et al. систематизирует worked-example effect и пользу self-explanation; IES/WWC даёт moderate evidence для чередования worked solutions и problem solving [ES-L31, ES-L01].
- **Ограничения/противоречия.** Expertise reversal: объяснение, полезное новичку, становится лишней нагрузкой эксперту. Пассивное чтение примера слабее сравнения/самообъяснения; поверхностно похожий пример может провоцировать копирование.
- **Кому подходит.** Новички и новый тип многошаговой задачи; продвинутым — как редкий reference или contrastive expert solution.
- **Ошибка внедрения.** Показать polished notebook без решений «почему»; дать пример с теми же числами; держать полный пример после стабильного mastery.
- **AI/ML и Arena mechanic.** Annotated pipeline с decision points: why split first, baseline, metric, leakage check. Затем completion example с пропусками, потом самостоятельный вариант.
- **Проверочная метрика.** Решение structurally similar и transfer problem при равном времени; число скопированных surface steps против корректных principles; cognitive-load probe вторичен.
- **Возможный negative effect.** Иллюзия понимания, copying, подавление самостоятельного поиска и expertise reversal.

#### M20 — Scaffolding / строительные леса

- **Определение.** Временная, диагностически связанная помощь, позволяющая выполнить часть задачи, пока самостоятельное выполнение недоступно: decomposition, cue, representation, question, tool constraint.
- **Доказательства.** **Moderate** в computer-based STEM/problem-centered contexts. Belland et al. meta-analysis: 144 experimental studies, 333 outcomes, средний `g=0.46`, положительные результаты по возрастам; effect различался по уровню assessment, а не сводился к одному типу scaffolding [ES-L32].
- **Ограничения/противоречия.** Высокая неоднородность, много author-designed measures; наличие dynamic fading не показало однозначного преимущества в этом synthesis. Scaffolding — широкая категория.
- **Кому подходит.** Все, если помощь зависит от состояния; особенно новичок в ill-structured STEM task.
- **Ошибка внедрения.** Полное решение под кнопкой «hint»; одинаковая лестница всем; помощь ради completion; не учитывать, какая подсказка уже была открыта.
- **AI/ML и Arena mechanic.** Лестница: (1) цель проверки, (2) контрвопрос, (3) relevant invariant, (4) partial representation, (5) worked step. Каждая ступень логируется и снижает independence evidence, но не XP как наказание.
- **Проверочная метрика.** Последующее выполнение без scaffold, hint depth/skill, transfer и время до independent recovery; не текущий completion.
- **Возможный negative effect.** Help abuse, learned helplessness, алгоритмическое недооценивание ученика и скрытое снижение task standard.

#### M21 — Fading / постепенное снятие опор

- **Определение.** Систематическое уменьшение worked steps, cues или tutor control по мере появления компетентности; backward/forward fading — разные схемы заполнения решения.
- **Доказательства.** **Moderate** как часть worked-example/scaffolding literature; отдельная универсальная причинная база слабее. Belland meta-analysis не нашёл, что наличие/логика изменения scaffolding стабильно модерировали outcome; следовательно, «fading всегда лучше» не подтверждено [ES-L32].
- **Ограничения/противоречия.** Фиксированный fade может быть слишком быстрым/медленным; self-selected help смешивает способность и мотивацию. Expertise reversal поддерживает снятие redundancy, но не конкретный алгоритм.
- **Кому подходит.** После первого успешного guided performance; динамика должна учитывать качество и задержку, а не число кликов.
- **Ошибка внедрения.** Снять после одной удачи; оставить «мягкую» подсказку навсегда; карать запрос помощи; менять одновременно task difficulty и help.
- **AI/ML и Arena mechanic.** Снять одну ступень после двух независимых успешных variants в разные сессии; вернуть только ближайшую опору при повторе одного error family; периодически probe без hints.
- **Проверочная метрика.** Вероятность успеха после removal, relapse rate, help requests и delayed independence; safety bound — рост repeated failure/quit.
- **Возможный negative effect.** Premature fading вызывает серию неудач; late fading — зависимость и завышенный mastery.

#### M22 — Cognitive load theory / теория когнитивной нагрузки

- **Определение.** Instructional design должен учитывать ограниченность рабочей памяти при работе с новой взаимосвязанной информацией и использовать знания в long-term memory как схемы; современная CLT избегает простого «intrinsic/germane/extraneous score» как трёх измеримых баков.
- **Доказательства.** **Moderate** как theory family с множеством experimental effects (worked example, split attention, expertise reversal); Sweller, van Merriënboer & Paas 2019 описывают развитие теории, а обзор CLT в computing education отмечает конкурирующие версии и предположение мотивации [ES-L33, ES-L34].
- **Ограничения/противоречия.** Subjective load scales шумны, механизм отдельных effects оспаривается, motivation/affect часто вынесены за модель. «Коротко» не автоматически означает низкую нагрузку.
- **Кому подходит.** Особенно новичкам и сложным multi-representation tasks; эксперту та же помощь может мешать.
- **Ошибка внедрения.** Убрать любую сложность; дробить целостный reasoning на бессвязные screens; использовать декоративную анимацию; разнести код, plot и объяснение по вкладкам.
- **AI/ML и Arena mechanic.** Интегрировать dataset schema, code и relevant output; progressive disclosure; pretrain essential vocabulary; убрать competition chrome во время сложного reasoning.
- **Проверочная метрика.** Learning/time и error types при randomized interface; subjective effort + task performance, а не один self-report; проверить novice/expert interaction.
- **Возможный negative effect.** Over-simplification убирает productive effort и целостность проекта; «нейро»-риторика маскирует taste decisions.

#### M23 — Desirable difficulties / желательные трудности

- **Определение.** Условия, которые могут ухудшать performance во время acquisition, но улучшать долговременное удержание/перенос (spacing, retrieval, variation); трудность желательна только при доказанном delayed выигрыше и достижимости.
- **Доказательства.** **Moderate** как объединяющий framework, опирающийся на сильные эффекты отдельных manipulations. Soderstrom & Bjork review показывает расхождение learning и текущей performance; Bjork et al. демонстрируют boundary conditions testing [ES-L35, ES-L36].
- **Ограничения/противоречия.** Нет единого «эффекта трудности»; difficulty может быть просто нежелательной из-за отсутствия prior knowledge, disability, language или feedback. Post hoc label опасен.
- **Кому подходит.** Learner с recovery path и базовой схемой; индивидуальная калибровка обязательна.
- **Ошибка внедрения.** Намеренно запутанный UI, таймер, наказание, отсутствие примера; считать frustration признаком deep learning.
- **AI/ML и Arena mechanic.** Убрать шаблон выбора метода на consolidation item, сменить dataset/context и отложить повтор; оставить ясную цель и доступный rescue scaffold.
- **Проверочная метрика.** Delayed/transfer gain при допустимых failure, distress и dropout; current accuracy ожидаемо может снизиться и не служит единственным stop rule.
- **Возможный negative effect.** Disengagement, inequity, тревога и закрепление ошибки; соревновательная difficulty может отбирать уже сильных.

### 4.7. Генерация, объяснение и саморегуляция

#### M24 — Generation effect / эффект генерации

- **Определение.** Лучше запоминается информация, которую человек сам производит (ответ, completion, пример, hypothesis), чем эквивалентная прочитанная; generation должна быть выполнимой и затем проверенной.
- **Доказательства.** **Moderate** для памяти. Meta-analysis Bertsch et al. формализует общий положительный generation effect, но величина зависит от материала, rule и between/within-subject design [ES-L37].
- **Ограничения/противоречия.** Типичный outcome — память слов/фактов, не ML problem solving. Ошибочная генерация без corrective study может вредить; слишком трудная задача не запускает полезный процесс.
- **Кому подходит.** После контекста/partial cue; свободная генерация сложнее для новичка и учащегося на неродном языке.
- **Ошибка внедрения.** Blank page до обучения; принять любой текст; раскрыть ответ в placeholder; мерить длину.
- **AI/ML и Arena mechanic.** Ученик прогнозирует learning curve/ошибку, пишет pseudo-code или создаёт counterexample до просмотра expert answer; потом сравнивает по структурной рубрике.
- **Проверочная метрика.** Delayed recall/transfer generated elements против read-only при равном времени; factual error persistence.
- **Возможный negative effect.** Уверенная выдумка, extra load и memorization собственной неправильной формулировки.

#### M25 — Self-explanation / самообъяснение

- **Определение.** Ученик выводит причинные/концептуальные связи, объясняет шаг и связывает его с prior knowledge; пересказ и «мне понятно» не считаются.
- **Доказательства.** **Moderate**. Bisra et al. meta-analysis: 64 reports, 69 effect sizes, общий random-effects `g=0.55`; эффекты обнаружены в разных tasks/levels, но prompts и качество объяснений различались [ES-L38]. IES/WWC присваивает strong evidence deep explanatory questions [ES-L01].
- **Ограничения/противоречия.** Content-specific prompts полезнее абстрактного «объясни». Self-explanation может улучшить learning, но не metacognitive accuracy; LLM легко создаёт красивый текст вместо ученика.
- **Кому подходит.** От старшего школьного возраста; младшим — sentence stems/oral explanation; всем нужен пример качественного causal link.
- **Ошибка внедрения.** Обязательные 500 слов; auto-grade по fluency; принять tautology; AI переписывает за ученика.
- **AI/ML и Arena mechanic.** После каждой ключевой design choice — один вопрос по misconception: «почему scaling до split даёт leakage?» Ответ проверяется rule-based claims/targeted rubric; затем counterexample.
- **Проверочная метрика.** Rubric causal completeness и последующий transfer, а не length/readability; provenance/keystroke не доказывают learning, но помогают audit.
- **Возможный negative effect.** Overload, verbal advantage bias, рационализация случайно верного ответа и генеративный ghostwriting.

#### M26 — Metacognition / метапознание

- **Определение.** Знание о собственном обучении плюс планирование, мониторинг и регулирование стратегии; confidence — лишь один несовершенный сигнал.
- **Доказательства.** **Moderate**. Donker et al. meta-analysis learning-strategy instruction показывает пользу явной, контекстной strategy instruction; de Boer et al. 48 interventions обнаружил сохранение долгосрочных effects, но package включает разные стратегии и outcomes [ES-L39, ES-L40].
- **Ограничения/противоречия.** Self-report плохо отражает реальное действие; domain-general советы переносятся хуже встроенных. Повышение confidence не равно accuracy.
- **Кому подходит.** Все, но prompts адаптируются к возрасту; младшим — observable choices вместо абстрактного журнала.
- **Ошибка внедрения.** Опрос «как хорошо понял?» без проверки; dashboard confidence как рейтинг; общие советы вне конкретной задачи.
- **AI/ML и Arena mechanic.** До ответа ученик оценивает confidence и выбирает план проверки; после outcome видит calibration bucket и должен выбрать next action из 2–3 вариантов.
- **Проверочная метрика.** Brier score/ECE для confidence, resolution между known/unknown, качество next-action selection и delayed performance.
- **Возможный negative effect.** Rumination, gaming self-report, shame за overconfidence и автоматическое ограничение пути по шумной confidence.

#### M27 — Reflection / рефлексия

- **Определение.** Структурированный разбор опыта: ожидание → evidence → причина расхождения → конкретное изменение → проверка в следующем действии. Это ретроспективная регуляция, не эссе о чувствах.
- **Доказательства.** **Limited**. Meta-analysis 2023 reflective interventions сообщает положительный academic effect, но смешивает форматы/режимы и имеет обычные риски author measures; systematic review graduate medical education подчёркивает нехватку связи с patient-level/professional outcomes [ES-L41, ES-L42].
- **Ограничения/противоречия.** Reflection трудно валидно оценивать, social desirability высока; письмо привилегирует вербально сильных. Причинность конкретного компонента неясна.
- **Кому подходит.** После значимой ошибки/проекта; младшим — короткий guided oral/choice+evidence формат.
- **Ошибка внедрения.** Дневник после каждого экрана; оценивать «глубину личности»; хранить чувствительный текст; reflection без следующей проверки.
- **AI/ML и Arena mechanic.** Error log из четырёх полей: predicted cause, evidence missed, rule, next trigger. При похожем кейсе система возвращает только trigger и сравнивает новое действие.
- **Проверочная метрика.** `reflection_follow_through`: доля заявленных changes, применённых релевантно; recurrence same error family и transfer, не sentiment.
- **Возможный negative effect.** Ритуальный текст, самобичевание, privacy exposure и LLM-generated pseudo-reflection.

### 4.8. Перенос, адаптация и формат подачи

#### M28 — Transfer / перенос обучения

- **Определение.** Успешное применение знания в ситуации, отличающейся от practice. Near/far — не бинарный ярлык: Barnett & Ceci предлагают описывать, что изменилось (домен знания, физический/социальный/временной/функциональный контекст, modality) [ES-L43].
- **Доказательства.** Как **исход** — обязателен; как самостоятельный «метод» — **Insufficient**. Near transfer достижим чаще; general far-transfer claims спорны. Retrieval/testing переносится на непроверенное знание слабее, чем на tested content [ES-L04].
- **Ограничения/противоречия.** «Far» часто определяется post hoc; отсутствие переноса может означать отсутствие cue, а не знания. Один новый датасет с тем же шаблоном — surface variation, не far transfer.
- **Кому подходит.** Всем, но дистанция от practice растёт постепенно; новичку сначала structurally similar, затем контекстно новый case.
- **Ошибка внедрения.** Называть рандомизацию чисел transfer; тестировать неизвестный prerequisite; использовать один item; давать hints из учебного шаблона.
- **AI/ML и Arena mechanic.** Transfer ladder: новые значения → новый dataset той же структуры → другой домен с тем же принципом → открытый brief с выбором workflow. Items из закрытого банка и без lesson labels.
- **Проверочная метрика.** Матрица `trained / near / structural / cross-context` × `immediate / 14d / 30d`; report по каждой клетке, без одного «transfer score».
- **Возможный negative effect.** Слишком далёкий тест измеряет prior domain knowledge/язык и ложно объявляет неуспех; высокий stakes демотивирует.

#### M29 — Adaptive learning / адаптивное обучение

- **Определение.** Система изменяет следующее содержание, помощь, порядок или сложность на основе learner evidence; адаптация темпа не должна менять стандарт компетенции.
- **Доказательства.** **Moderate** для хорошо спроектированных ITS, не для любого AI recommender. Kulik & Fletcher meta-analysis 50 controlled evaluations поддерживает ITS в среднем; Steenbergen-Hu & Cooper K–12 mathematics нашли лишь `g≈0.01–0.09` и возможную меньшую пользу для low achievers, тогда как college synthesis сообщил `g≈0.32–0.37` [ES-L44, ES-L45, ES-L46].
- **Ограничения/противоречия.** ITS bundles (content, hints, time, mastery) не изолируют «адаптивность». Сравнения часто с business-as-usual, а не равноценной nonadaptive платформой. Domain and implementation matter.
- **Кому подходит.** Большой разброс prior knowledge; только при периодических unbiased probes и возможности оспорить/сбросить модель.
- **Ошибка внедрения.** Оптимизировать click/accuracy; навсегда упростить путь; обучать model на best score; непрозрачный ability label.
- **AI/ML и Arena mechanic.** Bayesian/IRT knowledge state предлагает next evidence с максимальной информацией под prerequisite constraints; 10–20% заданий — общие anchor/probe; learner выбирает challenge/route в безопасном диапазоне.
- **Проверочная метрика.** Randomized adaptive vs yoked/nonadaptive при равном контенте/времени: delayed mastery, time-to-mastery, calibration и subgroup gaps. Off-policy replay — только предварительный анализ.
- **Возможный negative effect.** Filter bubble, widening gap, privacy/profiling, self-fulfilling low track и нестабильная сложность.

#### M30 — Microlearning / микрообучение

- **Определение.** Короткая, целевая единица контента/практики на одну достижимую цель. Это формат масштаба и доступа, а не отдельный механизм консолидации.
- **Доказательства.** **Limited**. Scoping review De Gagne et al. нашёл лишь 17 eligible studies (2 228 участников) в health professions до 2019 и призвал изучать higher-level outcomes/practice; определения различались [ES-L47]. Более новые reviews остаются неоднородными по duration, intervention и outcome.
- **Ограничения/противоречия.** «Короткое» смешано со spacing, mobile delivery, retrieval и multimedia; нельзя приписать эффект длине. Сложные модели требуют непрерывного reasoning.
- **Кому подходит.** Refresher, prerequisite, just-in-time check; не замена notebook/project/debugging session.
- **Ошибка внедрения.** Разрезать причинную цепь на карточки; TikTok-видео без retrieval; обещать retention из-за 5 минут; оптимизировать streak.
- **AI/ML и Arena mechanic.** 3–7-минутный retrieval/diagnostic unit возвращает в 25–60-минутную целостную lab; каждая micro-unit имеет цель, attempt, feedback и future retrieval.
- **Проверочная метрика.** Delayed learning per minute и transfer против эквивалентного цельного формата; completion/DAU — операционные, не causal learning metrics.
- **Возможный negative effect.** Fragmentation, shallow fluency, notification fatigue и неспособность удерживать длинную цепь анализа.

### 4.9. Ошибка как материал и обучение через объяснение другим

#### M31 — Productive failure / продуктивная неудача

- **Определение.** Ученик сначала пытается решить новую, доступную по prerequisites проблему и генерирует representations/solutions, затем получает explicit consolidation, сравнивающую попытки с canonical concepts. Это не «бросить в глубокую воду».
- **Доказательства.** **Moderate** при fidelity. Sinha & Kapur meta-analysis: 53 studies, 166 comparisons, problem solving → instruction превосходило instruction → problem solving в среднем `g=0.36 [0.20; 0.51]`; сильнее при конструктивных особенностях Productive Failure и соответствующей population/task [ES-L48].
- **Ограничения/противоречия.** Средний эффект зависит от prior knowledge, duration, grouping, outcome и quality consolidation. Отсутствие initial success не является целью; PF evidence не разрешает unguided discovery.
- **Кому подходит.** Учащиеся с нужными foundations; задача в зоне, где можно создать частичные решения. Для слабого новичка — pretraining/representations.
- **Ошибка внедрения.** Нет последующей консолидации; непосильный challenge; оценочный штраф за первую попытку; сразу дать hints, исключив генерацию.
- **AI/ML и Arena mechanic.** До урока о imbalance ученик предлагает metric/resampling на небольшом кейсе; Arena сохраняет reasoning, затем сравнивает 3 student approaches и canonical trade-offs; завершает новым dataset.
- **Проверочная метрика.** Conceptual/transfer delayed test против instruction-first при равных content/time; diversity/quality initial representations — mediator, не конечная цель.
- **Возможный negative effect.** Фрустрация, stereotype threat, запоминание неверного решения и потеря времени при плохой consolidation.

#### M32 — Error-based learning / обучение на ошибках

- **Определение.** Ошибка диагностируется по типу и используется для corrective feedback, contrast, повторного извлечения и будущего распознавания; «ошибка разрешена» без коррекции — не метод.
- **Доказательства.** **Moderate**. Metcalfe Annual Review суммирует лабораторные данные: для neurologically typical learners errorful generation с корректирующим feedback часто полезнее абсолютного избегания ошибок; high-confidence errors могут особенно хорошо корректироваться (hypercorrection), но есть важные population/task boundaries [ES-L49].
- **Ограничения/противоречия.** Errorless learning бывает предпочтительнее при некоторых memory impairments; собственная ошибка может интерферировать; classroom/project evidence меньше лабораторной memory base.
- **Кому подходит.** Типичные учащиеся в безопасном low-stakes sandbox; специальные потребности требуют отдельной оценки.
- **Ошибка внедрения.** Красивый «fail forward» без precise correction; публичный shame; каталог exact answers вместо error families; повторять ошибку без correct retrieval.
- **AI/ML и Arena mechanic.** Versioned taxonomy `leakage/preprocessing`, `metric/objective`, `validation/sampling`, `causal claim`, `reproducibility`; после correction — contrastive pair и delayed recurrence probe.
- **Проверочная метрика.** Recurrence hazard конкретного error family, correction durability, confidence shift и ability обнаружить ошибку в чужом pipeline.
- **Возможный negative effect.** Reinforcement misconception, shame/avoidance, чрезмерный remedial tracking и ложная диагностика системой.

#### M33 — Learning by teaching / обучение через преподавание

- **Определение.** Ученик готовится объяснить материал и реально учит/отвечает на вопросы другого человека или teachable agent; подготовка и интерактивное объяснение — разные механизмы.
- **Доказательства.** **Moderate**. Kobayashi meta-analysis 28 studies: preparing-to-teach `g=0.35`, teaching after preparation `g=0.56`; interactive teaching сильнее noninteractive. Гетерогенность высокая (`I²` до 93%), 24/28 studies — участники ≥18 лет [ES-L50].
- **Ограничения/противоречия.** Ограниченная база для детей; teaching package включает expectancy, retrieval, explanation и feedback. Качество объяснения/вопросов может быть низким.
- **Кому подходит.** Старшие школьники/студенты после initial mastery; младшим — короткий teachable character с vetted questions.
- **Ошибка внедрения.** Записать видео в пустоту; оценивать charisma; заставить слабого ученика учить неизвестное; AI-agent всегда соглашается.
- **AI/ML и Arena mechanic.** «Научи Arena-бота отличать validation от test»: bot задаёт scripted misconceptions/counterexamples, ученик исправляет; ответы grounded в competency rubric и проходят factual checks.
- **Проверочная метрика.** Индивидуальный delayed/transfer test учителя, factuality/causal completeness объяснения и ответ на novel student question; views/likes не считаются.
- **Возможный negative effect.** Распространение ошибки, performance anxiety, extra workload и иллюзия знания из fluent presentation.

## 5. Двадцать принципов Arena

**Уверенность набора принципов:** высокая для запрета смешивать XP/activity/assisted completion с mastery и для требования независимого evidence; средне-высокая для retrieval, feedback, spacing и transfer loop; средняя для порядка scaffolding/fading, interleaving и командно-проектных механик; низкая для любых конкретных порогов и интервалов до Arena trials. Это strength конкретных решений, не рейтинг источников.

1. **Измерять изменение, не активность.** XP, streak, session count и completion не входят в mastery decision.
2. **Каждая ключевая идея проходит цикл** `model/example → unaided attempt → feedback → variant retry → delayed retrieval → unseen transfer`.
3. **Ответ фиксируется до подсказки.** Иначе невозможно различить знание, recognition и копирование.
4. **Помощь — данные, а не проступок.** Hint level снижает силу evidence, но не унижает и не отнимает earned social status.
5. **Best score не равен mastery.** Решение использует несколько независимых evidence в разные дни.
6. **Mastery не понижает одна поздняя ошибка.** Состояние хранит uncertainty и историю; новая ошибка запускает probe, а не стирает достижение.
7. **Банки learning и assessment разделены.** Турнирные/transfer items закрыты, versioned и проверены на exposure/leakage.
8. **Новичку — guidance, эксперту — fading.** Уровень поддержки зависит от prior evidence и expertise reversal checks.
9. **Interleaving после первичной схемы.** Сначала понять метод, затем учиться выбирать между похожими методами.
10. **Timing feedback — task-dependent design hypothesis.** Arena отдельно проверяет immediate feedback для новой/каскадирующей ошибки, end-of-attempt feedback для целостного reasoning и действительно time-delayed feedback; ни один режим не считается универсально лучшим.
11. **Ошибка завершается правильным извлечением.** Одного показа правильного ответа недостаточно.
12. **Проект не заменяет индивидуальную проверку.** Командный артефакт всегда сопровождает individual defense/unseen task.
13. **AI-наставник не решает за ученика.** Минимальная подсказка, grounded feedback, полный solution только в явно помеченном worked-example режиме.
14. **Адаптация меняет маршрут, не стандарт.** Общие anchor items и периодические unbiased probes предотвращают low-track trap.
15. **Reflection имеет будущую проверку.** Запись без observable next action не evidence обучения.
16. **Каждая компетенция связана с артефактами.** Task/version, контекст, help, reviewer, rubric и время сохраняются.
17. **Transfer специфицируется.** Arena указывает, что именно новое: данные, representation, домен, modality, delay или collaboration.
18. **Время и благополучие — guardrails.** Learning gain не оправдывает excess frustration, dropout, sleep disruption или subgroup harm.
19. **Маркетинговое утверждение требует продукта-доказательства.** Внешний meta-analysis обосновывает механизм, но не claim «Arena улучшает результат на X%».
20. **Сначала пилот и репликация.** Новый mechanic проходит instrument validation → small randomized pilot → delayed follow-up → subgroup audit → staged rollout.

## 6. Модель измерения реального обучения

### 6.1. Что именно считается результатом

Единица измерения — не урок и не аккаунт, а тройка:

`learner i × competency k × evidence event e`.

Каждое событие обязано хранить:

- `competency_id` и versioned definition/rubric;
- `item_id`, `item_version`, family/template и difficulty estimate;
- novel ли item для ученика и видел ли он structural sibling;
- target outcome: recall, procedure, discrimination, explanation, near/structural/cross-context transfer;
- timestamp и delay от instruction/предыдущего exposure;
- исходный committed response и финальный response;
- correctness/rubric dimensions и scorer/version;
- hint count, максимальную глубину, показ worked solution/AI assistance;
- collaboration mode, reviewer и provenance артефакта;
- confidence до feedback;
- error-family tags до и после correction;
- duration и технические сбои;
- assessment purpose: practice/formative/probe/certification/tournament.

Событие без version/provenance нельзя использовать для high-stakes mastery.

### 6.2. Assessment stack и параллельные формы

| Момент | Форма | Назначение | Правило |
|---|---|---|---|
| `T−` | **Pre A** | prior knowledge/readiness | до instruction; без feedback до завершения baseline |
| `T0` | **Post B** | acquisition | параллельная, не повтор A и не practice items |
| `T14` | **Delay C** | удержание 14 дней | закрытый банк; отсутствие lesson cue; no hints в primary endpoint |
| `T30` | **Delay D** | удержание 30 дней | новая параллельная форма + anchor items |
| `TX` | **Transfer E** | перенос | невиданный контекст/representation; prerequisites измерены отдельно |
| `TP` | **Common probe** | сравнимость адаптивных путей | случайные anchor/probe, одинаковый стандарт для всех |

Параллельные формы строятся из blueprint по компетенции, cognitive demand, misconception, representation и difficulty. «Поменять числа» недостаточно. Все operational/high-stakes items проходят content, accessibility и fairness review. Для open coding/project responses заранее заданная выборка проходит blind double scoring; при малом pilot — все responses, при большом — объём, рассчитанный под требуемую точность CI для κ/ICC, а не фиксированные 20–30%. Anchor items не должны становиться practice content. Exposure rate и компрометация банка мониторятся; скомпрометированный item выводится с version boundary [ES-L51, ES-L52].

Окна `T14`, `T30`, правило изменения измерений между формами и доля anchor/probe — стартовые Arena conventions. Их валидируют через response-process studies, form equivalence, measurement invariance и прогноз следующей независимой задачи; они не следуют автоматически из learning-science meta-analyses.

Для открытых AI/ML задач форма считается параллельной, если сохраняет целевой principle, но меняет минимум два поверхностных измерения и одно контекстное: dataset/domain, target distribution, representation, tool constraints или decision consequences. Transfer form меняет ещё и cue/functional context, но не добавляет неизмеренный prerequisite.

### 6.3. Базовые оценки и формулы

Если банк и sample действительно достаточны, основной scale может использовать IRT/Rasch или many-facet model для rubric scores с uncertainty. Выбор модели разрешён только после проверки dimensionality, local dependence, fit, стабильности item parameters, equating/linking и measurement invariance/DIF; IRT не является автоматическим default. При малом пилоте используются заранее заданные scaled rubric scores и item-level mixed models; простые проценты публикуются только рядом с числом и сложностью items [ES-L51, ES-L52].

Обозначим `θᵢkt` — latent/standardized skill learner `i`, competency `k`, time `t`.

**Acquisition:**

```text
G0ᵢk = θᵢk,T0 − θᵢk,pre
```

**Удержанный прирост:**

```text
G14ᵢk = θᵢk,T14 − θᵢk,pre
G30ᵢk = θᵢk,T30 − θᵢk,pre
```

**Забывание после post:**

```text
D14ᵢk = θᵢk,T0 − θᵢk,T14
D30ᵢk = θᵢk,T0 − θᵢk,T30
```

Отношение retention `G14/G0` допускается только exploratory при `G0>ε`: ratio нестабилен около нуля и не является primary metric. «Normalized gain» `(post−pre)/(max−pre)` не используется как основной causal outcome из-за ceiling и зависимости от baseline.

**Transfer** публикуется вектором, не одним числом:

```text
Tᵢk = [accuracy_near,
       accuracy_structural,
       accuracy_cross_context,
       rubric_open_artifact]
```

Для каждой компоненты фиксируются distance dimensions по Barnett–Ceci taxonomy. Если нужен агрегат для внутреннего ranking experiments, веса preregistered и результат всегда показывается вместе с компонентами; агрегат не становится learner-facing «IQ».

### 6.4. Уверенность и калибровка

Перед feedback ученик сообщает вероятность правильности `p∈{0, .25, .5, .75, 1}` либо компактную ordinal scale, заранее откалиброванную.

Для binary outcome:

```text
Brierᵢk = (1/n) Σₑ (pₑ − yₑ)²      # меньше лучше
```

Expected calibration error:

```text
ECEᵢk = Σ_b (n_b/n) · |mean(p_b) − mean(y_b)|
```

Обязательно также report **resolution**: отличает ли ученик свои правильные и неправильные ответы. Низкий Brier при постоянных 50% не означает полезный monitoring. Confidence не влияет на доступ к курсу сам по себе; оно используется для reflection/feedback и research.

Learner-level Brier/ECE публикуются только при заранее заданном минимальном `n` и достаточном числе observations в bins; иначе используются cohort/hierarchical estimates с uncertainty. ECE — описательная метрика, чувствительная к binning, и не служит единственным основанием для персонального решения.

### 6.5. Подсказки и независимость

Во всех файлах этапа используется единый `assistance_code`; числовой код не равен номеру `H`, потому что `0` зарезервирован за полностью самостоятельным первым committed response:

```text
0 = first committed response до любого feedback
1 = checker-only feedback = H0
2 = goal/cue = H1
3 = principle/representation = H2
4 = partial step/strategy = H3
5 = worked step/analogous worked example = H4
6 = full solution/bottom-out = H5
```

Только `assistance_code=0` может быть кандидатом в независимый класс `I3/I4`; он не подтверждает mastery сам по себе и всё равно проходит полную conjunction из §6.7. Любое решение после `assistance_code≥1`, включая H0 checker feedback, является assisted current performance. Последующая новая recovery-задача без AI снова получает code `0` и может стать `I3/I4`, если удовлетворяет требованиям novelty, формы и контроля. Три разные метрики не смешиваются:

```text
HelpBurdenᵢk = Σ assistance_weightₑ / valid_opportunities
AssistanceLiftᵢk = P(correct_current | randomized hint)
                   − P(correct_current | matched no-hint)
HintDependencyᵢk = P(error_unaided_delayed | prior randomized hint)
                   − P(error_unaided_delayed | prior matched no-hint)
```

`AssistanceLift` показывает текущую помощь, а не зависимость. Положительный `HintDependency` означает больше будущих ошибок без помощи после hinted practice. Обе причинные разницы требуют randomized/yoked assignment, одинаковых content, времени и delayed no-hint probes; сырая разница обычных попыток confounded, потому что hint выбирают на более трудных items. При self-selected hints показатели описательны и не трактуются причинно.

**Independence evidence** — отдельные категории:

- `I0`: чужое/полное решение доступно;
- `I1`: совместная работа, индивидуальный вклад не изолирован;
- `I2`: AI/peer feedback или partial scaffold;
- `I3`: unaided controlled task;
- `I4`: unaided unseen transfer/certification task.

Similarity/plagiarism detectors только отправляют на human review; они не являются доказательством нарушения и не снижают mastery автоматически. Для командного проекта нужен минимум один `I3/I4` evidence на каждого участника.

### 6.6. Повторяемость ошибок

Error фиксируется на уровне семейства, а не exact item. После первой корректировки начинается риск-период до независимой проверки:

```text
ErrorRecurrence14ᵢkf = recurrent_errors_family_f_within_14d
                       / valid_independent_opportunities_family_f
```

Дополнительно оценивается time-to-recurrence/hazard с censoring: ученик без следующей возможности не считается «исправившимся». Critical errors (data leakage, use of test set in selection, fabricated evidence, privacy violation) имеют отдельный status `unresolved/resolved` и требуют контрпримера + delayed probe.

### 6.7. Состояния mastery и decision rule

Learner-facing состояния:

1. **Not observed** — данных нет.
2. **Developing** — есть guided/partial evidence.
3. **Provisional** — успешное unaided acquisition, ещё нет задержки/переноса.
4. **Confirmed** — выполнено conjunctive rule ниже.
5. **Needs refresh** — evidence устарело или uncertainty выросла; это не «отобрали навык».
6. **Contested** — новый critical error противоречит mastery; нужен targeted probe.

При достаточном банке и валидированной measurement model вычисляется posterior только по независимому evidence; `I0–I2` не входят в `θ_unaided`, если модель заранее не оценивает отдельный help effect:

```text
Pᵢk = Pr(θᵢk,unaided ≥ θ_mastery,k | valid I3/I4 evidence)
```

Операционально это явная conjunction:

```text
Confirmed = model_confidence
            AND independent_family_coverage
            AND elapsed_spacing
            AND delayed_evidence
            AND unseen_transfer
            AND no_unresolved_critical_error
            AND valid_form
```

`Confirmed` разрешён только если **одновременно**:

- `Pᵢk ≥ 0.90`; либо заранее заданный консервативный эквивалент для малого pilot без псевдоточного posterior;
- минимум 2 успешных `I3` attempts на разных item families, разделённых предзаданным минимальным elapsed lag `Δmin,k`, а не просто сменой календарной даты;
- минимум 1 `I4` unseen/structural transfer success;
- есть valid delayed evidence в предзаданном окне вокруг `T14` (для foundation skills после валидации добавляется окно `T30`);
- последняя delayed попытка не использовала hint/solution;
- нет unresolved critical error family;
- форма имеет допустимую reliability/exposure и не скомпрометирована.

Порог `0.90`, `Δmin,k`, число evidence и окна `T14/T30` — проектные starting rules, не «научные константы»; их валидируют против стоимости false mastery/false non-mastery, burden и subgroup gaps. Более высокий threshold может потребоваться для safety/privacy skills, но тоже требует decision analysis. Одна поздняя ошибка не перезаписывает историю и не понижает статус немедленно: она создаёт `Contested`, обновляет uncertainty и запускает новый независимый probe. Best score также не удерживает mastery вопреки устойчивым новым данным.

### 6.8. Программа causal evaluation

Для каждого крупного mechanic формулируются treatment, active control, primary outcome и окно *до* просмотра данных.

**Предпочтительный person-level ANCOVA** для одного post/delay outcome на ученика:

```text
θᵢ,post/delay = β0 + β1·Treatment_assignment(i) + β2·θᵢ,pre
                 + u_class(i) + εᵢ
```

`u_learner` добавляется только при нескольких repeated outcomes одного learner; `item` здесь отсутствует. Для item/rubric-level данных используется отдельный GLMM:

```text
g(E[Yᵢjkt]) = β0 + β1·Treatment_assignment(i) + β2·baselineᵢk
              + β3·time_t + β4·Treatment×time
              + u_learner(i) + u_class(i) + u_item(j)
```

- Primary estimand — intention-to-treat; exposure/per-protocol — secondary.
- Link `g` и distribution задаются outcome; для ordinal rubric не применяется автоматически binary logistic model.
- Report `β1`, 95% CI/credible interval, cluster-adjusted Hedges `g` при уместности и raw-scale difference.
- При school/class rollout randomize cluster и учитывать ICC; power/MDE и sample size считают по числу и неравным размерам кластеров, а не по числу учеников. При малом числе кластеров нужны small-sample corrections либо randomization inference [ES-L53, ES-L54].
- До запуска фиксируются fidelity measures, cross-condition contamination/spillover, доступ учителя к обеим механикам и способ обработки post-randomization joiners.
- Multiple primary outcomes ограничить или корректировать; exploratory labels явны.
- Missing 14/30-day outcomes: attrition по condition/subgroup, sensitivity/bounds, не complete-case silence.
- Novelty effect: минимум одна реплика после 4–8 недель и анализ cohort/teacher effects.
- Учитель/контент/время должны быть равны active control настолько, насколько это возможно; фактическое различие и intervention fidelity измеряются, а не предполагаются [ES-L53].

Минимальные пилоты:

| Вопрос | Treatment | Active control | Primary endpoint |
|---|---|---|---|
| retrieval | commit answer + feedback | равноценное restudy/answer exposure | `G14`, unseen items |
| spacing | adaptive schedule | same items/time, massed или fixed | retention curve 14/30 |
| interleaving | mixed similar families | blocked, equal exposure | method-selection transfer |
| feedback timing | immediate/end-block | same feedback content | transfer 7/14, dependency |
| adaptive | learner-model route | yoked/nonadaptive same pool | `G30`, time-to-mastery, gaps |
| productive failure | attempt→consolidation | instruction→matched practice | conceptual transfer 14d |
| AI hints | minimal grounded ladder | static validated hints | unaided transfer + factual harm |

### 6.9. Reliability, validity и leakage audit

Перед causal claim инструмент проходит:

- content validity: два независимых AI/ML SME + learning designer сверяют blueprint;
- response-process check: cognitive interviews подтверждают, что item вызывает целевой reasoning;
- scorer reliability: weighted κ/ICC и adjudication для open artifacts;
- item fit/difficulty/discrimination; локальная независимость, если используется IRT;
- parallel-form equivalence и anchor drift;
- DIF/subgroup review по возрасту, языку, полу (если законно/этично собирать), disability/access mode и исходной подготовке;
- predictive validity на следующей независимой задаче, без circular reuse rubric;
- exposure, screenshot/public-solution monitoring и teacher leakage protocol;
- versioned change log: изменение wording/rubric/model scorer разрывает временной ряд или проходит bridge study.

Высокая Cronbach alpha сама по себе не доказывает ни одномерность, ни transfer validity. Автоматический LLM scorer не становится ground truth: он сравнивается с blinded human double-scoring, проходит adversarial/fairness набор и имеет abstain/escalate.

### 6.10. Guardrails и stop rules

Ни один learning gain не проходит rollout, если:

- растёт dropout/avoidance или median burden непропорционален эффекту;
- ухудшается результат low-baseline/accessibility subgroup при общей средней пользе;
- AI feedback factual critical-error rate превышает заранее заданный safety threshold;
- hint system повышает current completion, но снижает unaided `T14/TX`;
- tournament/leaderboard condition повышает anxiety, harassment или cheating signal;
- attrition к `T14/T30` различается так, что вывод неустойчив к plausible bounds;
- инструмент не имеет приемлемой scorer/parallel reliability;
- privacy/consent для несовершеннолетних не соответствует применимому праву и минимизации данных.

Алгоритм не диагностирует dyslexia, ADHD, «способность» или карьерную пригодность. Sensitive inference запрещён; учащийся и педагог видят основание рекомендации, могут выбрать альтернативу и запросить review.

### 6.11. Dashboard: что показывать, а что запрещено смешивать

Показывать отдельно:

- `acquisition`, `retention 14/30`, `transfer by distance`;
- unaided/guided evidence;
- confidence calibration;
- unresolved error families;
- time/attempt cost и дату следующего refresh;
- uncertainty и количество evidence.

Не создавать единый vanity «Learning Score», который складывает XP, скорость, quiz accuracy, project likes и рейтинг. Если бизнесу нужен north-star, безопаснее использовать cohort-level `share of started competencies confirmed at T14 with unseen evidence`, рядом с denominators, time cost, attrition и subgroup gaps.

## 7. Policy: strength of evidence → сила продуктового утверждения

### 7.1. Три независимые оценки

Arena хранит отдельно три разные оценки:

- **Source reliability A–D** — надёжность каждого отдельного источника строго по `00_research_plan.md`;
- **Mechanism strength High / Moderate / Limited / Insufficient** — насколько совокупность литературы поддерживает механизм и конкретный outcome;
- **Arena claim grade 0–4** — насколько собственные данные подтверждают конкретную реализацию, аудиторию и outcome.

| Arena grade | Требование | Разрешённая формулировка |
|---|---|---|
| **0** | только литература/дизайн | «механика основана на исследованном принципе» |
| **1** | usability + валидированный instrument, без контроля | «пилот показывает выполнимость»; не effectiveness |
| **2** | preregistered controlled test, валидный immediate outcome | «в этом пилоте улучшился такой-то post outcome» |
| **3** | randomized/credible quasi-experiment, `T14/T30`, unseen transfer, attrition/subgroups | ограниченный причинный claim для этой population/version |
| **4** | независимая/многоцентровая репликация, operational harms и durability | устойчивый claim в очерченных контекстах |

Source reliability **A** и даже mechanism strength **High** не превращают Arena grade 0 в grade 3. Изменение core mechanic, model, scoring rubric, target age или curriculum version может понизить переносимость собственного evidence.

### 7.2. Inclusion и обновление

- Приоритет: systematic review/meta-analysis с прозрачным поиском и controlled studies → preregistered/RCT/robust field experiment → authoritative practice guide → narrative/scoping/theory.
- Для learning outcome нужны объективные knowledge/skill/retention/transfer measures; engagement sources поддерживают только engagement claim.
- Проверять контроль, assignment, attrition, independence, instrument proximity, delay, sample/domain/country, heterogeneity и conflicts.
- Preprint не используется как единственная опора production claim; retraction/correction проверяется при каждом квартальном evidence refresh.
- Классическая работа не исключается по возрасту, но её применимость проверяется более новыми synthesis и локальными данными.
- Каждая цифра effect size сопровождается population, comparator, outcome и caveat; запрещено переводить `g` в «процентов лучше» без исходной шкалы.
- Нулевой/отрицательный результат сохраняется в registry. Cherry-picking только успешных cohorts запрещён.
- Review: критические AI/safety sources — ежеквартально; learning-science synthesis — раз в год или при крупном новом review; ссылки и corrections — автоматически/ежеквартально.

### 7.3. Decision template для механики

```text

```

Если поле comparator, delayed outcome или harm пусто, документ нельзя использовать для claim «улучшает обучение».

## 9. Что пока нельзя утверждать

- Нельзя утверждать, что конкретный schedule Arena лучше фиксированного, пока нет randomized delayed comparison.
- Нельзя утверждать, что AI Coach обучает лучше static hints или человека: ITS meta-analyses не являются evidence современных LLM.
- Нельзя считать ML-проект доказательством индивидуальной компетенции без независимой защиты/transfer task.
- Нельзя переносить classroom average effect на российскую школьную аудиторию без локальной культурно-языковой валидации; у classroom retrieval review мало non-WEIRD studies.
