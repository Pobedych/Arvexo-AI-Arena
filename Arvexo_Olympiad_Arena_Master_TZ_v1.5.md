# Arvexo Olympiad Arena — Master TZ v1.5

Статус: рабочий проект ТЗ для MVP.

## 1. Цель MVP

Создать простую образовательную платформу, на которой пользователь может:

1. войти или зарегистрироваться через Arvexo Account;
2. выбрать AI Track;
3. последовательно изучать материалы и выполнять задания;
4. получить приглашение на AI-турнир;
5. зарегистрироваться на турнир и пройти его;
6. увидеть свой результат и разбор ошибок.

Главный пользовательский путь MVP:

> Вход через Arvexo Account → AI Track → Обучение → Приглашение → Турнир → Результат

MVP считается успешным, если новый пользователь может пройти весь этот путь без помощи администратора.

## 2. Объём первой версии

### 2.1 Входит в MVP

- авторизация через существующий Arvexo Account;
- базовый профиль пользователя;
- один образовательный трек — AI Track;
- разделы, темы, уроки и практические задания;
- сохранение прогресса обучения;
- AI-турниры с автоматической проверкой ответов;
- приглашение всех активных учеников AI Track на новый турнир;
- регистрация пользователя на турнир;
- ограничение турнира по времени;
- автоматический подсчёт результата;
- таблица результатов турнира;
- просмотр правильных ответов и объяснений после завершения турнира;
- простая административная панель для управления учебными материалами и турнирами.

### 2.2 Не входит в MVP

- Mathematics Track и Algorithm Track;

- сложные достижения, сезоны и дивизионы;
- командные турниры;
- автоматизированный античит на основе ИИ.

Эти функции могут быть добавлены после проверки основного пользовательского пути.

## 3. Роли

### 3.1 Пользователь

Может:

- войти через Arvexo Account;
- заполнить базовый профиль;
- выбрать AI Track;
- открывать доступные уроки;
- выполнять учебные задания;

Может:

- скрывать некорректные результаты;

## 4. AI Track

AI Track состоит из следующей иерархии:

> Трек → Раздел → Тема → Урок → Задания

Каждый урок содержит:

- название;
- теоретический материал;
- необязательные иллюстрации или ссылки;
- набор практических заданий;
- отметку о прохождении.

В MVP поддерживаются следующие типы учебных заданий:

- выбор одного ответа;
- выбор нескольких ответов;
- короткий текстовый ответ;
- числовой ответ.

Урок считается завершённым, когда пользователь ознакомился с материалом и выполнил обязательные задания с установленным проходным результатом.

### 4.1 Быстрая практика (Practice Mode)

Дополнительно к последовательному прохождению уроков в MVP доступен режим быстрой практики — короткая тренировка вперемешку по темам AI Track перед турниром.

Правила режима:

- пользователю случайно выбирается небольшой набор опубликованных заданий (по умолчанию 3) из всех опубликованных уроков AI Track, без привязки к текущему открытому уроку;
- порядок и состав вопросов не совпадают между попытками;
- ответ на каждое задание проверяется сразу на backend, пользователь сразу видит результат и объяснение;
- режим не учитывает и не изменяет прогресс прохождения уроков — это тренировка, а не часть обязательной программы;
- прохождение практики можно повторять без ограничений;
- задания для практики берутся из общего банка заданий (см. §14.7), отдельного банка для практики не создаётся.

Быстрая практика не заменяет обязательные задания урока и не влияет на статус завершения урока или расчёт общего прогресса (§11).

## 5. Первый формат AI-турнира

Первый AI-турнир проверяет знания по темам AI Track и не требует обучения или загрузки ML-моделей.

Турнир содержит задания следующих типов:

- выбор одного ответа;
- выбор нескольких ответов;
- короткий текстовый ответ;
- числовой ответ.

Для каждого задания администратор задаёт:

- условие;
- тип ответа;
- правильный ответ;
- количество баллов;
- объяснение решения;
- порядок отображения.

Основные правила MVP:

- турнир индивидуальный;
- у турнира есть время начала и завершения;
- после старта участнику предоставляется единый ограниченный интервал времени;
- участник может отправить итоговые ответы один раз;
- незавершённая попытка автоматически отправляется после истечения времени;
- результат рассчитывается как сумма баллов за правильные ответы;
- штраф за неправильный ответ отсутствует;
- при равном количестве баллов выше располагается участник, завершивший турнир раньше;
- ответы и объяснения открываются только после общего завершения турнира.

## 6. Приглашение на турнир

После публикации турнира система приглашает всех активных пользователей AI Track.

В MVP приглашение отображается:

- внутри платформы;
- на главной странице пользователя;
- в разделе турниров.

Отправка email и push-уведомлений не обязательна для первой версии.

Пользователь должен явно нажать кнопку «Участвовать». После регистрации турнир появляется в списке предстоящих турниров пользователя.

## 7. Результат турнира

После завершения турнира пользователь видит:

- набранные баллы;
- максимальное количество баллов;
- место среди участников;
- время прохождения;
- ответы пользователя;
- правильные ответы;
- объяснения решений.

Таблица результатов содержит:

- место;
- отображаемое имя пользователя;
- количество баллов;
- время прохождения.

В MVP результат турнира не изменяет Arena Score. Рейтинговая система добавляется после проверки базовой механики турниров.

## 8. Критерии готовности MVP

MVP готов, когда выполняются все условия:

1. Новый пользователь может войти через Arvexo Account и открыть AI Track.
2. Пользователь может пройти урок, ответить на задания и увидеть сохранённый прогресс.
3. Администратор может без изменения кода создать и опубликовать турнир.
4. Активный пользователь AI Track автоматически получает приглашение.
5. Пользователь может зарегистрироваться и пройти турнир в заданное время.
6. Таймер продолжает работать корректно после обновления страницы или повторного входа.
7. После окончания времени система больше не принимает изменения ответов.
8. Результаты рассчитываются автоматически и одинаково для всех участников.
9. Правильные ответы не раскрываются до завершения турнира.
10. После завершения турнира пользователь видит результат, место и разбор заданий.

## 10. Учебная программа AI Track для MVP

### 10.1 Целевая аудитория

Программа рассчитана на школьников 7–11 классов, которые ранее могли не изучать искусственный интеллект и машинное обучение.

Для начала обучения не требуются знания высшей математики или опыт программирования. Термины объясняются простым языком, а задания проверяют понимание идей, а не запоминание определений.

### 10.2 Результат обучения

После прохождения программы пользователь должен:

- понимать, что такое искусственный интеллект и машинное обучение;
- отличать обучение с учителем от обучения без учителя;
- понимать назначение данных, признаков и целевой переменной;
- различать задачи классификации, регрессии и кластеризации;
- понимать разделение данных на обучающую и тестовую выборки;
- знать базовые метрики качества моделей;
- распознавать переобучение и утечку данных;
- понимать основные ограничения и риски AI-систем;
- быть готовым пройти первый теоретический AI-турнир.

### 10.3 Структура программы

#### Раздел 1. Введение в искусственный интеллект

Урок 1. Что такое искусственный интеллект

- определение AI;
- примеры AI-систем;
- отличие AI от обычной программы.

Урок 2. Как машина обучается на данных

- данные и закономерности;
- обучение и применение модели;
- простая схема работы ML-системы.

Урок 3. Основные виды машинного обучения

- обучение с учителем;
- обучение без учителя;
- обучение с подкреплением на уровне общего знакомства.

#### Раздел 2. Данные и задачи машинного обучения

Урок 4. Объекты, признаки и целевая переменная

- объект наблюдения;
- признаки;
- целевая переменная;
- примеры табличных данных.

Урок 5. Классификация, регрессия и кластеризация

- постановка каждой задачи;
- примеры из реальной жизни;
- выбор подходящего типа задачи.

Урок 6. Подготовка данных

- пропущенные значения;
- категориальные и числовые признаки;
- ошибки и смещения в данных.

#### Раздел 3. Обучение и оценка модели

Урок 7. Обучающая, валидационная и тестовая выборки

- зачем разделять данные;
- почему нельзя проверять модель на данных обучения;
- понятие честной оценки.

Урок 8. Метрики качества

- accuracy;
- precision и recall на интуитивном уровне;
- MAE для задач регрессии;
- выбор метрики в зависимости от задачи.

Урок 9. Переобучение и утечка данных

- признаки переобучения;
- утечка целевой переменной;
- примеры нечестной проверки модели.

#### Раздел 4. Ответственный искусственный интеллект

Урок 10. Ошибки и ограничения AI

- модель может ошибаться;
- качество результата зависит от данных;
- уверенный ответ не гарантирует правильность.

Урок 11. Смещения, приватность и безопасность

- смещения в выборке;
- персональные данные;
- последствия автоматических решений.

Урок 12. Человек и искусственный интеллект

- где AI помогает человеку;
- где требуется контроль человека;
- ответственное использование AI в обучении и соревнованиях.

### 10.4 Объём урока

Один урок MVP должен занимать 10–20 минут и содержать:

- короткий теоретический материал;
- 1–3 примера;
- 3–5 обязательных заданий;
- объяснение после каждого проверенного ответа;
- итоговый результат урока.

Для каждого задания обязательно хранится объяснение правильного ответа. Пользователь видит его после отправки ответа в учебном режиме.

## 11. Прогресс обучения

Прогресс рассчитывается по обязательным урокам AI Track.

Урок получает один из статусов:

- `not_started` — не начат;
- `in_progress` — начат, но не завершён;
- `completed` — завершён.

Урок считается завершённым, если пользователь набрал не менее 70% баллов за обязательные задания.

Основные правила:

- уроки открываются последовательно внутри раздела;
- первый урок доступен сразу после выбора AI Track;
- следующий урок открывается после завершения предыдущего;
- учебные задания можно проходить повторно без ограничений;
- в прогрессе сохраняется лучший результат;
- общий прогресс равен доле завершённых обязательных уроков;
- незавершённая попытка сохраняется автоматически.

На главной странице AI Track отображаются:

- текущий урок;
- общий процент прогресса;
- завершённые разделы;
- ближайший доступный турнир.

## 12. Связь обучения с турниром

У каждого турнира администратор указывает разделы и уроки, знания по которым проверяются.

После публикации турнира приглашение получают все активные пользователи AI Track. Приглашение содержит:

- название турнира;
- дату и время проведения;
- продолжительность;
- список проверяемых тем;
- рекомендуемый уровень подготовки пользователя.

Рекомендуемый уровень рассчитывается по прогрессу в связанных уроках:

- «Готов» — завершено не менее 70% связанных уроков;
- «Стоит подготовиться» — завершено менее 70% связанных уроков.

Уровень подготовки носит рекомендательный характер. В MVP пользователь может зарегистрироваться на турнир при любом прогрессе обучения.

Первый турнир рекомендуется проводить по материалам всех четырёх разделов и включать 20 заданий:

- 8 заданий с одним вариантом ответа;
- 4 задания с несколькими вариантами ответа;
- 4 задания с коротким ответом;
- 4 задания с числовым ответом.

Рекомендуемая продолжительность первого турнира — 60 минут. Максимальный результат — 100 баллов.

## 13. Механика AI-турнира в MVP

AI-турнир в MVP должен работать как простой проверочный экзамен внутри AI Track. Пользователь не обязан понимать сложные правила: он получает приглашение, подтверждает участие, проходит задания в отведённое время и получает результат после завершения турнира.

### 13.1 Пользовательский сценарий

Базовый сценарий участия:

1. Пользователь учится в AI Track.
2. Администратор публикует AI-турнир.
3. Пользователь получает приглашение внутри платформы.
4. Пользователь нажимает «Участвовать».
5. До старта пользователь видит страницу турнира: дату, время, длительность, темы, количество заданий и правила.
6. После старта турнира пользователь может нажать «Начать».
7. После начала попытки запускается индивидуальный таймер.
8. Пользователь решает задания.
9. Пользователь нажимает «Завершить» или система автоматически завершает попытку по таймеру.
10. После завершения турнира пользователь видит результат, место, правильные ответы и объяснения.

### 13.2 Статусы турнира

Турнир имеет один из статусов:

- `draft` — черновик, доступен только администратору;
- `published` — опубликован, приглашения отправлены, пользователи могут зарегистрироваться;
- `active` — турнир идёт, зарегистрированные пользователи могут начать попытку;
- `finished` — турнир завершён, доступны результаты и разбор;
- `cancelled` — турнир отменён администратором.

### 13.3 Статусы участия пользователя

Участие пользователя в турнире имеет один из статусов:

- `invited` — пользователь приглашён, но ещё не подтвердил участие;
- `registered` — пользователь подтвердил участие;
- `in_progress` — пользователь начал прохождение;
- `submitted` — пользователь отправил ответы;
- `auto_submitted` — ответы отправлены системой по истечении времени;
- `missed` — пользователь зарегистрировался, но не начал попытку до завершения турнира.

### 13.4 Правила времени

У турнира есть общий период проведения: дата и время начала, дата и время окончания.

У каждой попытки есть индивидуальная длительность, например 60 минут.

Правила запуска попытки:

- пользователь может начать попытку только в период, когда турнир находится в статусе `active`;
- пользователь может начать попытку в любой момент внутри общего периода проведения;
- после нажатия «Начать» запускается индивидуальный таймер;
- если до окончания общего периода осталось меньше индивидуальной длительности, таймер ограничивается оставшимся временем;
- после истечения таймера система автоматически отправляет сохранённые ответы;
- после отправки ответов пользователь не может изменить попытку.

Пример: турнир идёт с 10:00 до 18:00, длительность попытки — 60 минут. Если пользователь начал в 17:30, его попытка продлится 30 минут, а не 60.

### 13.5 Формат заданий

В MVP AI-турнир использует те же типы заданий, что и учебный режим:

- один вариант ответа;
- несколько вариантов ответа;
- короткий текстовый ответ;
- числовой ответ.

Для каждого задания администратор задаёт:

- текст задания;
- тип задания;
- варианты ответа, если применимо;
- правильный ответ;
- количество баллов;
- объяснение правильного ответа;
- связанную тему или урок AI Track.

### 13.6 Оценивание в MVP

В MVP используется простая система оценивания без штрафов.

Правила начисления баллов:

- за правильный ответ пользователь получает полный балл за задание;
- за неправильный ответ пользователь получает 0 баллов;
- за пропущенный ответ пользователь получает 0 баллов;
- штрафы за неправильные ответы не применяются;
- итоговый результат равен сумме баллов за все задания.

Проверка по типам заданий:

- один вариант ответа — правильным считается только выбранный верный вариант;
- несколько вариантов ответа — правильным считается только точное совпадение выбранного набора вариантов с правильным набором;
- короткий текстовый ответ — ответ сравнивается после нормализации строки: удаление лишних пробелов, приведение к одному регистру;
- числовой ответ — ответ сравнивается с правильным значением; если для задания задана допустимая погрешность, она учитывается.

### 13.7 Рейтинг и тайбрейкеры

После завершения турнира формируется таблица результатов.

Порядок сортировки участников:

1. Больше итоговых баллов.
2. Меньше время прохождения.
3. Раньше время отправки попытки.

Если все три условия совпадают, участники получают одинаковую позицию или сортируются по внутреннему идентификатору попытки. Для MVP допустимо использовать одинаковую позицию.

### 13.8 Разбор после турнира

Разбор становится доступен после перехода турнира в статус `finished`.

В разборе пользователь видит:

- свой итоговый результат;
- максимальный возможный результат;
- место в таблице;
- время прохождения;
- список заданий;
- свой ответ по каждому заданию;
- правильный ответ;
- объяснение;
- связанную тему или урок AI Track;
- кнопку «Повторить тему», если задание связано с уроком.

В MVP правильные ответы и объяснения не показываются сразу после отправки попытки, если турнир ещё не завершён. Это снижает риск передачи ответов другим участникам.

### 13.9 Минимальный контроль честности в MVP

В MVP не используются камера, прокторинг, блокировка вкладок, запись экрана и сложный античит.

Минимальные правила честности:

- одна попытка на пользователя;
- случайный порядок заданий для каждого участника;
- случайный порядок вариантов ответа, если это не ломает смысл задания;
- запрет изменения ответов после отправки;
- логирование времени приглашения, регистрации, старта попытки, отправки и автоотправки;
- хранение IP-адреса и user-agent попытки только если это допустимо политикой приватности платформы.

Если пользователь обновил страницу или временно потерял соединение, попытка не должна сбрасываться. Ответы сохраняются автоматически, а таймер продолжает идти на сервере.

### 13.10 Что добавляется после MVP

После MVP в турнирную механику можно добавить более сложные правила:

- штрафы за неправильные ответы;
- частичные баллы для заданий с несколькими вариантами ответа;
- разные веса заданий по сложности;
- отдельные правила для быстрых ответов;
- ограничения на поздний старт попытки;
- апелляции по результатам;
- ручную проверку отдельных заданий;
- расширенный античит;
- подозрительные паттерны прохождения;
- сезонный рейтинг и влияние турниров на Arena Score;
- командные турниры;
- турниры с задачами по программированию, математике и ML-практике.

Для MVP эти функции не входят в обязательный объём, но архитектура турниров не должна мешать их добавлению в будущих версиях.

## 14. Административная панель MVP

Административная панель нужна, чтобы команда Arvexo могла самостоятельно управлять AI Track и первым форматом турниров без участия разработчиков в каждом изменении контента.

В MVP админка должна быть простой и функциональной. Её задача — не заменить полноценную LMS, а дать минимальный набор инструментов для запуска обучения и AI-турниров.

### 14.1 Роли в админке

В MVP достаточно одной административной роли:

- `admin` — может управлять треками, уроками, заданиями, турнирами, приглашениями и результатами.

После MVP можно добавить более детальные роли:

- `content_editor` — управляет уроками и заданиями, но не видит персональные данные пользователей;
- `tournament_manager` — создаёт и проводит турниры;
- `support` — смотрит пользователей и помогает решать проблемы;
- `super_admin` — управляет администраторами и системными настройками.

### 14.2 Основные разделы админки

В MVP админка состоит из следующих разделов:

1. Дашборд.
2. Пользователи.
3. Треки.
4. Уроки.
5. Банк заданий.
6. Турниры.
7. Результаты турниров.

Этого достаточно, чтобы собрать полный путь пользователя: регистрация → выбор AI Track → обучение → приглашение → турнир → результат.

### 14.3 Дашборд администратора

На дашборде администратор видит краткое состояние платформы:

- количество зарегистрированных пользователей;
- количество пользователей, выбравших AI Track;
- количество активных пользователей AI Track;
- средний прогресс по AI Track;
- ближайший турнир;
- количество приглашённых пользователей;
- количество зарегистрированных участников турнира;
- количество завершённых попыток последнего турнира.

Для MVP дашборд может быть информационным, без сложной аналитики и графиков.

### 14.4 Управление пользователями

Администратор может:

- просматривать список пользователей;
- искать пользователя по имени, email или ID;
- открывать карточку пользователя;
- видеть выбранный трек;
- видеть прогресс по AI Track;
- видеть участие пользователя в турнирах;
- видеть статус последней турнирной попытки;
- вручную отправить пользователю приглашение на опубликованный турнир;
- заблокировать или разблокировать пользователя, если это требуется для безопасности.

В MVP администратор не редактирует учебные ответы пользователя и не меняет результаты турниров вручную. Если требуется исправление результата, это должно быть отдельной функцией после MVP с журналом изменений.

### 14.5 Управление треками

В MVP доступен один основной трек — AI Track.

Администратор может:

- видеть список треков;
- открыть карточку AI Track;
- редактировать название и описание трека;
- менять статус трека: `draft`, `published`, `archived`;
- управлять порядком разделов внутри трека.

В MVP создание дополнительных треков через админку необязательно. Архитектура должна позволять добавить Math Track, Algorithm Track и другие треки позже.

### 14.6 Управление уроками

Администратор может создавать и редактировать структуру AI Track:

- разделы;
- темы;
- уроки;
- порядок уроков;
- статус урока.

Урок имеет поля:

- название;
- краткое описание;
- раздел;
- порядковый номер;
- теоретический материал;
- список связанных заданий;
- минимальный процент для завершения урока;
- статус: `draft`, `published`, `archived`.

Правила публикации урока:

- урок в статусе `draft` виден только администратору;
- урок в статусе `published` доступен пользователям по правилам открытия прогресса;
- урок в статусе `archived` не доступен новым пользователям, но может сохраняться в истории для тех, кто уже проходил его ранее.

Для MVP теоретический материал урока может храниться в простом текстовом или Markdown-формате.

### 14.7 Банк заданий

Банк заданий — единое место, где администратор создаёт задания для учебного режима и турниров.

Задание имеет поля:

- название для администратора;
- текст задания;
- тип задания;
- варианты ответа, если применимо;
- правильный ответ;
- допустимая погрешность для числового ответа, если применимо;
- количество баллов;
- объяснение правильного ответа;
- связанный трек;
- связанный раздел;
- связанный урок или тема;
- уровень сложности: `easy`, `medium`, `hard`;
- статус: `draft`, `published`, `archived`.

Поддерживаемые типы заданий в MVP:

- один вариант ответа;
- несколько вариантов ответа;
- короткий текстовый ответ;
- числовой ответ.

Администратор может:

- создать задание;
- отредактировать задание;
- найти задание по названию, теме, типу или статусу;
- привязать задание к уроку;
- использовать опубликованное задание в турнире;
- архивировать задание.

Если задание уже использовалось в завершённом турнире, его нельзя менять так, чтобы это изменило исторические результаты. Для такого случая администратор должен создать новую версию задания.

### 14.8 Управление турнирами

Администратор может создать AI-турнир из админки.

Турнир имеет поля:

- название;
- описание;
- трек;
- связанные разделы и уроки;
- дата и время начала;
- дата и время окончания;
- индивидуальная длительность попытки;
- список заданий;
- максимальный балл;
- правила для участника;
- статус: `draft`, `published`, `active`, `finished`, `cancelled`.

Администратор может:

- создать черновик турнира;
- добавить задания из банка заданий;
- изменить порядок заданий для базового отображения;
- включить случайный порядок заданий для участников;
- включить случайный порядок вариантов ответа;
- посмотреть предпросмотр турнира как пользователь;
- опубликовать турнир;
- отменить турнир;
- завершить турнир вручную, если это требуется.

Перед публикацией система должна проверить минимальные условия:

- указаны название и описание;
- указаны дата начала и дата окончания;
- указана длительность попытки;
- добавлено хотя бы одно задание;
- у всех заданий есть правильные ответы;
- у всех заданий есть баллы;
- у всех заданий есть объяснения;
- максимальный балл рассчитан корректно.

### 14.9 Приглашения на турнир

После публикации турнира система автоматически создаёт приглашения для активных пользователей AI Track.

Администратор может:

- увидеть список приглашённых пользователей;
- увидеть статус каждого приглашения;
- вручную отправить приглашение конкретному пользователю;
- повторно отправить приглашение, если пользователь его не увидел;
- посмотреть количество пользователей, подтвердивших участие.

В MVP приглашения отправляются внутри платформы. Email, push-уведомления, Telegram и другие каналы можно добавить после MVP.

Статусы приглашения:

- `created` — приглашение создано;
- `seen` — пользователь увидел приглашение;
- `accepted` — пользователь нажал «Участвовать»;
- `declined` — пользователь отказался, если такая функция включена;
- `expired` — турнир завершился, приглашение больше не актуально.

### 14.10 Результаты турниров

Администратор может открыть страницу результатов турнира.

На странице результатов отображаются:

- список участников;
- статус попытки каждого участника;
- итоговый балл;
- максимальный балл;
- место в рейтинге;
- время начала попытки;
- время отправки;
- длительность прохождения;
- способ отправки: вручную или автоматически;
- ответы пользователя по заданиям.

Администратор может:

- фильтровать участников по статусу;
- искать пользователя;
- открыть детальную попытку пользователя;
- экспортировать результаты в CSV;
- открыть публичную таблицу лидеров, если она включена.

В MVP результаты не редактируются вручную. Любые будущие ручные корректировки должны сохраняться в журнале аудита.

### 14.11 Журнал действий администратора

В MVP желательно, но не обязательно, сохранять базовый журнал административных действий.

Минимально полезные события:

- создание урока;
- публикация урока;
- создание задания;
- изменение задания;
- публикация турнира;
- отмена турнира;
- ручное завершение турнира;
- ручная отправка приглашения;
- блокировка пользователя.

Для каждого события сохраняется:

- ID администратора;
- тип действия;
- объект действия;
- дата и время;
- краткое описание изменения.

Если журнал действий не входит в самый первый релиз, его нужно оставить как обязательный кандидат на ближайшую версию после MVP.

### 14.12 Ограничения админки в MVP

В MVP в админку не входят:

- визуальный конструктор сложных курсов;
- импорт заданий из Excel или Google Sheets;
- массовая ручная проверка;
- роли и права доступа по организациям;
- сложная аналитика удержания;
- A/B-тесты;
- управление платежами;
- управление партнёрами;
- продвинутый античит;
- настройка сезонных рейтингов.

Эти функции можно добавить после проверки базового пользовательского пути.

### 14.13 Критерии готовности админки MVP

Админка MVP считается готовой, если администратор может без помощи разработчика:

1. Опубликовать AI Track.
2. Создать раздел, тему и урок.
3. Добавить теорию в урок.
4. Создать задания для урока.
5. Опубликовать урок.
6. Создать AI-турнир.
7. Добавить в турнир задания из банка.
8. Опубликовать турнир.
9. Увидеть список приглашённых пользователей.
10. Увидеть зарегистрированных участников.
11. Открыть результаты турнира.
12. Экспортировать результаты.

Если эти действия работают, MVP закрывает административный контур для первого запуска.

### 15.3 Обязательная авторизация через Arvexo Account

В MVP регистрация и вход в Arvexo Olympiad Arena должны выполняться через `https://account.arvexo.ru`.

Arena не должна иметь отдельную независимую систему аккаунтов, если Arvexo Account доступен для интеграции.

Базовый сценарий входа:

1. Пользователь нажимает «Войти» или «Зарегистрироваться» в Arena.
2. Arena перенаправляет пользователя на Arvexo Account.
3. Пользователь проходит вход или регистрацию.
4. Arvexo Account возвращает пользователя обратно в Arena.
5. Arena создаёт или обновляет локальный профиль пользователя на основе данных Arvexo Account.
6. Пользователь продолжает путь: выбор трека → обучение → приглашение → турнир.

### 15.4 Локальный профиль Arena

Arvexo Account является источником истины для учётной записи пользователя.

Arena хранит только данные, необходимые для образовательного и турнирного сценария:

- внутренний ID профиля Arena;
- ID пользователя из Arvexo Account;
- отображаемое имя;
- email, если он передан и разрешён;
- выбранный трек;
- прогресс обучения;
- приглашения на турниры;
- попытки турниров;
- результаты;
- настройки уведомлений внутри Arena.

Arena не должна хранить пароль пользователя. Пароль, восстановление доступа, подтверждение email и базовая безопасность аккаунта относятся к Arvexo Account.

### 15.5 Требования к SSO-интеграции

Точный протокол интеграции определяется реализацией Arvexo Account.

Для MVP допустимы следующие варианты:

- OAuth 2.0 / OpenID Connect;
- собственный token-based flow Arvexo Account;
- server-side session flow, если он уже используется в экосистеме.

Независимо от выбранного протокола должны быть реализованы:

- безопасный redirect после входа;
- защита от подмены redirect URL;
- получение стабильного ID пользователя;
- создание локального профиля Arena при первом входе;
- обновление базовых данных профиля при повторном входе;
- выход из Arena;
- корректная обработка истёкшей сессии;
- запрет доступа к обучению, турнирам и админке без авторизации.

### 15.6 Единая навигация экосистемы

Если в экосистеме Arvexo используется общий header или список продуктов, Arena должна поддерживать переходы:

- на основной сайт Arvexo;
- в Arvexo Connect;
- в Arvexo AI;
- в Arvexo Account;
- обратно в Arena.

В MVP достаточно простого верхнего меню:

- логотип Arvexo;
- название модуля Arena;
- ссылка на AI Track;
- ссылка на турниры;
- ссылка на профиль;
- кнопка входа или меню пользователя.

### 15.7 Админка и Arvexo Account

Административный доступ в Arena также должен быть связан с Arvexo Account.

В MVP возможна простая схема:

- пользователь входит через Arvexo Account;
- Arena проверяет локальный список администраторов по Account ID или email;
- если пользователь есть в списке администраторов, ему доступна админка;
- если пользователя нет в списке, доступ запрещён.

После MVP можно вынести роли и права полностью в Arvexo Account, если там появится централизованное управление доступами.

### 15.8 Требования к UX единого входа

Пользователь не должен чувствовать, что проходит отдельную регистрацию в Arena.

Требования:

- кнопки должны называться «Войти через Arvexo» или «Продолжить с Arvexo Account»;
- после входа пользователь возвращается на ту страницу Arena, с которой начал сценарий;
- если пользователь открыл приглашение на турнир без входа, после авторизации он возвращается к этому приглашению;
- если пользователь уже авторизован в Arvexo Account, вход в Arena должен проходить без повторного ввода данных, если это поддерживается Account;
- ошибки входа должны быть понятными и не раскрывать лишние технические детали.

### 15.9 Что не входит в MVP

В MVP не требуется:

- разрабатывать полностью независимый бренд Arena, оторванный от Arvexo;
- создавать отдельную регистрацию Arena;
- делать отдельное восстановление пароля в Arena;
- строить собственную систему ролей вместо Arvexo Account;
- синхронизировать платёжные подписки из других продуктов;
- показывать единый биллинг экосистемы;
- делать общий кабинет всех продуктов Arvexo внутри Arena.

### 15.10 Критерии готовности интеграции с экосистемой

Интеграция считается готовой для MVP, если:

1. Arena имеет собственный образовательный и соревновательный sub-brand, но явно остаётся частью Arvexo.
2. Пользователь может войти только через Arvexo Account.
3. После входа создаётся локальный профиль Arena.
4. Пользователь возвращается в нужный сценарий после авторизации.
5. Администратор входит через Arvexo Account и получает доступ к админке по разрешённому Account ID.
6. Arena не хранит пароли пользователей.
7. Header, кнопки, карточки, формы и таблицы соответствуют выбранному Arena moodboard и не конфликтуют с экосистемой Arvexo.

## 16. Технологический стек MVP

Arvexo Olympiad Arena MVP должен разрабатываться на едином согласованном технологическом стеке, чтобы продукт было проще поддерживать, расширять и интегрировать с другими сервисами экосистемы Arvexo.

Обязательный стек MVP:

- Frontend: Next.js;
- Backend: Python;
- Database: PostgreSQL.

Использование другого основного стека для MVP не допускается без отдельного согласования.

### 16.1 Frontend: Next.js

Пользовательский интерфейс Arena должен быть реализован на Next.js.

Next.js используется для:

- публичных страниц Arena;
- личного кабинета пользователя;
- страниц AI Track;
- страниц уроков;
- страниц турниров;
- страницы попытки турнира;
- таблицы результатов;
- административной панели;
- интеграции с Arvexo Account на уровне пользовательского интерфейса;
- применения общей дизайн-системы Arvexo.

Frontend отвечает за:

- отображение интерфейса;
- навигацию между сценариями;
- формы и клиентскую валидацию;
- отображение прогресса обучения;
- отображение таймера турнира;
- отправку ответов пользователя на backend;
- отображение результатов и разбора;
- работу с состояниями загрузки и ошибок.

Критически важные проверки, начисление баллов, контроль времени и права доступа не должны выполняться только на frontend. Эти правила должны проверяться на backend.

### 16.2 Backend: Python

Backend Arena должен быть реализован на Python.

Backend отвечает за:

- интеграцию с Arvexo Account;
- создание и обновление локального профиля пользователя;
- хранение прогресса обучения;
- управление треками, уроками и заданиями;
- управление турнирами;
- создание приглашений;
- запуск и завершение попыток;
- серверный контроль таймера;
- сохранение ответов;
- автоматическую проверку ответов;
- расчёт результатов;
- формирование таблицы лидеров;
- права доступа пользователя и администратора;
- административные операции;
- экспорт результатов;
- журналирование важных событий.

Для backend можно использовать Python-фреймворк, выбранный командой разработки. Рекомендуемые варианты:

- FastAPI;
- Django;
- Django Ninja.

Финальный выбор Python-фреймворка должен учитывать скорость разработки MVP, удобство админки, интеграцию с PostgreSQL и дальнейшее расширение платформы.

### 16.3 Database: PostgreSQL

PostgreSQL является основной базой данных Arena.

В PostgreSQL хранятся:

- пользователи Arena и связь с Arvexo Account;
- роли и административный доступ;
- треки;
- разделы;
- темы;
- уроки;
- задания;
- варианты ответов;
- прогресс обучения;
- турниры;
- приглашения;
- попытки;
- ответы пользователей;
- результаты;
- журнал административных действий;
- системные события, если они нужны для MVP.

PostgreSQL должен быть источником истины для образовательных и турнирных данных Arena.

### 16.4 Разделение ответственности frontend и backend

Frontend не должен самостоятельно принимать критические решения, влияющие на результат пользователя.

На backend должны выполняться:

- проверка авторизации;
- проверка прав доступа;
- проверка доступности урока;
- проверка возможности начать турнир;
- запуск серверного таймера попытки;
- автоотправка или принудительное завершение попытки по времени;
- проверка правильности ответов;
- расчёт баллов;
- расчёт места в рейтинге;
- защита от повторной отправки попытки;
- сохранение всех значимых действий.

Frontend может отображать предварительное состояние, но окончательное решение всегда принимает backend.

### 16.5 API между Next.js и Python backend

Next.js должен взаимодействовать с Python backend через API.

Для MVP допустимы:

- REST API;
- RPC-style HTTP API;
- GraphQL, если он уже используется в экосистеме Arvexo.

Рекомендуемый вариант для MVP — простой REST API, так как он проще для реализации, тестирования и поддержки.

API должен покрывать:

- текущего пользователя;
- профиль Arena;
- список треков;
- структуру AI Track;
- уроки;
- задания уроков;
- прогресс;
- быструю практику (случайные задания и проверку ответа вне уроков, см. §4.1);
- список турниров;
- приглашения;
- регистрацию на турнир;
- старт попытки;
- сохранение ответа;
- отправку попытки;
- результаты;
- таблицу лидеров турнира;
- админские операции.

### 16.6 Миграции и схема базы данных

Все изменения структуры PostgreSQL должны выполняться через миграции.

Требования:

- схема базы не меняется вручную на продакшене;
- каждая версия backend содержит необходимые миграции;
- миграции можно применить повторяемо в staging и production окружениях;
- критические таблицы имеют индексы для поиска и сортировки;
- связи между сущностями фиксируются внешними ключами там, где это оправдано.

### 16.7 Фоновые задачи

Для MVP могут потребоваться фоновые задачи:

- автоматическое завершение турниров;
- автоотправка попыток по истечении времени;
- пересчёт таблицы результатов;
- создание приглашений после публикации турнира;
- экспорт результатов.

Если команда хочет упростить первую версию, часть фоновых действий может выполняться синхронно при пользовательских или административных запросах. Но архитектура должна позволять добавить полноценный worker после MVP.

Для фоновых задач после MVP можно использовать:

- Celery;
- RQ;
- Dramatiq;
- встроенные scheduled jobs инфраструктуры.

### 16.8 Хранение файлов

В MVP желательно избегать сложного файлового хранения.

Если уроки содержат только текст, Markdown и простые задания, файлохранилище не требуется.

Если позже появятся изображения, вложения, датасеты или ML-файлы, нужно добавить отдельное объектное хранилище:

- S3-compatible storage;
- Yandex Object Storage;
- Selectel Object Storage;
- другое совместимое решение.

Загрузка моделей, датасетов и файлов с предсказаниями не входит в MVP.

### 16.9 Окружения

Для разработки и запуска MVP нужны минимум два окружения:

- staging — для проверки перед релизом;
- production — для реальных пользователей.

Желательно также иметь локальное окружение разработки через Docker Compose или аналогичный инструмент.

Минимальный состав окружения:

- Next.js frontend;
- Python backend;
- PostgreSQL;
- переменные окружения для интеграции с Arvexo Account;
- настройки CORS/CSRF;
- секреты для подписи сессий или токенов.

### 16.10 Критерии готовности технологического стека

Стек MVP считается готовым, если:

1. Next.js frontend запускается и работает с дизайном Arvexo.
2. Python backend предоставляет API для пользовательского и административного сценария.
3. PostgreSQL хранит все ключевые данные Arena.
4. Авторизация через Arvexo Account работает сквозным сценарием.
5. Frontend не содержит критической бизнес-логики скоринга и доступа.
6. Backend корректно проверяет права, время турнира и ответы.
7. Схема базы управляется миграциями.
8. Staging и production используют одинаковую архитектуру развертывания.

## 17. Страницы и навигация MVP

В MVP Arvexo Olympiad Arena должна иметь минимальный, но полный набор страниц, достаточный для основного пользовательского пути:

> Вход через Arvexo Account → выбор AI Track → обучение → приглашение → турнир → результат

Страницы должны быть реализованы на Next.js и визуально соответствовать продуктам экосистемы Arvexo.

### 17.1 Общая структура навигации

В MVP используется простая верхняя навигация.

Для неавторизованного пользователя:

- логотип Arvexo;
- название продукта Arena;
- ссылка на описание платформы;
- кнопка «Войти через Arvexo».

Для авторизованного пользователя:

- логотип Arvexo;
- AI Track;
- Турниры;
- Результаты;
- Профиль;
- меню пользователя.

Для администратора дополнительно:

- ссылка «Админка».

### 17.2 Публичные страницы

#### Главная страница Arena

Рекомендуемый route: `/`

Задача страницы — объяснить, что такое Arvexo Olympiad Arena и привести пользователя к входу через Arvexo Account.

На странице должны быть:

- короткое описание Arena;
- объяснение пути пользователя: учись → участвуй → получай результат;
- акцент на AI Track как первом доступном треке;

- кнопка «Войти через Arvexo»;
- ссылки на другие продукты экосистемы Arvexo, если это нужно в общей навигации.

#### Страница входа

Рекомендуемый route: `/login`

Страница не содержит собственной формы логина. Она перенаправляет пользователя в Arvexo Account или показывает кнопку «Продолжить с Arvexo Account».

После успешной авторизации пользователь возвращается в Arena.

Рекомендуемый route: `/auth/callback`

Техническая страница для обработки возврата из Arvexo Account.

Пользователь не должен надолго видеть эту страницу. После обработки авторизации система перенаправляет его:

- на onboarding, если пользователь впервые вошёл в Arena;
- на страницу, с которой он начал вход;
- на dashboard, если исходная страница неизвестна.

### 17.3 Onboarding и выбор трека

#### Страница первого входа

Рекомендуемый route: `/onboarding`

Показывается пользователю после первого входа через Arvexo Account, если у него ещё нет выбранного трека.

На странице должны быть:

- приветствие;
- краткое объяснение Arena;
- карточка AI Track;
- информация, что другие треки появятся позже;
- кнопка «Выбрать AI Track».

#### Страница выбора трека

Рекомендуемый route: `/tracks`

В MVP содержит только AI Track, но должна быть спроектирована так, чтобы позже добавить Math Track, Algorithm Track и другие направления.

Карточка трека содержит:

- название;
- описание;
- уровень сложности;
- примерную длительность;
- статус доступности;
- кнопку выбора или продолжения.

### 17.4 Личный кабинет пользователя

#### Dashboard пользователя

Рекомендуемый route: `/dashboard`

Главная страница авторизованного пользователя.

На странице отображаются:

- выбранный трек;
- текущий урок;
- общий прогресс;
- ближайший турнир;
- статус приглашения на турнир;
- последние результаты;

#### Профиль пользователя

Рекомендуемый route: `/profile`

### 17.5 Страницы AI Track

#### Главная страница AI Track

Рекомендуемый route: `/tracks/ai`

На странице отображаются:

- описание AI Track;

- список разделов;
- текущий рекомендованный урок;

#### Страница раздела

- название раздела;

Реализует режим быстрой практики, описанный в §4.1: короткая тренировка вперемешку по темам AI Track перед турниром.

На странице отображаются:

- случайно подобранный набор заданий (по умолчанию 3);
- текущий вопрос и варианты ответа;
- индикатор прогресса прохождения набора;
- проверка ответа сразу после отправки, с объяснением;
- счётчик правильных ответов;
- кнопка «Ещё раз» для получения нового случайного набора заданий;
- ссылка на страницу AI Track.

Результаты практики не сохраняются как часть прогресса обучения и не влияют на статус уроков.

### 17.6 Страницы турниров для пользователя

#### Список турниров

Рекомендуемый route: `/tournaments`

На странице отображаются:

- предстоящие турниры;
- активные турниры;
- завершённые турниры;
- статус участия пользователя;
- фильтр по статусу.

#### Страница турнира

Рекомендуемый route: `/tournaments/[tournamentId]`

До начала турнира страница показывает:

- название;
- описание;
- дату и время проведения;
- длительность попытки;
- проверяемые темы;
- количество заданий;
- правила;
- уровень готовности пользователя;
- кнопку «Участвовать».

Во время активного турнира страница показывает:

- статус регистрации;
- кнопку «Начать», если пользователь зарегистрирован и ещё не начал попытку;
- информацию об оставшемся времени общего периода.

После завершения турнира страница показывает:

- итоговую таблицу;
- ссылку на личный результат;
- разбор, если он доступен.

#### Страница попытки турнира

Рекомендуемый route: `/tournaments/[tournamentId]/attempt`

Это основная страница прохождения турнира.

На странице должны быть:

- таймер;
- список заданий или навигация по заданиям;
- текущее задание;
- варианты ответа или поле ответа;
- индикатор сохранения;
- кнопка «Завершить попытку»;
- предупреждение перед финальной отправкой.

Правила:

- страница доступна только участнику с активной попыткой;
- таймер должен синхронизироваться с backend;
- ответы должны автосохраняться;
- после отправки попытки пользователь перенаправляется на страницу ожидания или результата.

#### Страница ожидания результата

Рекомендуемый route: `/tournaments/[tournamentId]/submitted`

Показывается после отправки попытки, если турнир ещё не завершён.

На странице отображаются:

- подтверждение, что ответы отправлены;
- время отправки;
- информация, когда будут доступны результаты и разбор;
- ссылка на список турниров.

#### Страница результата турнира

Рекомендуемый route: `/tournaments/[tournamentId]/result`

На странице отображаются:

- итоговый балл пользователя;
- максимальный балл;
- место;
- время прохождения;
- список заданий;
- ответы пользователя;
- правильные ответы;
- объяснения;
- ссылки на связанные уроки.

Правильные ответы и объяснения показываются только после завершения турнира.

#### Таблица лидеров турнира

Рекомендуемый route: `/tournaments/[tournamentId]/leaderboard`

На странице отображаются:

- место;
- имя участника или публичное отображаемое имя;
- балл;
- время прохождения;
- статус попытки.

В MVP таблица лидеров доступна только пользователям, зарегистрированным на турнир (или уже отправившим попытку), и только после перехода турнира в статус `finished`. Пока турнир не завершён, страница показывает сообщение о том, что таблица откроется после завершения, без списка участников.

Порядок участников определяется тайбрейкерами из §13.7: больше баллов → меньше время прохождения → раньше время отправки попытки.

### 17.7 Страницы уведомлений

#### Уведомления пользователя

Рекомендуемый route: `/notifications`

В MVP уведомления могут быть простыми и использоваться для приглашений на турниры.

На странице отображаются:

- приглашения на турниры;
- изменение статуса турнира;
- доступность результатов;
- системные сообщения.

Если отдельная страница уведомлений не успевает в MVP, уведомления можно показывать на dashboard и в верхнем меню.

### 17.9 Страницы ошибок и служебные страницы

В MVP должны быть предусмотрены:

- `404` — страница не найдена;
- `403` — нет доступа;
- `500` — системная ошибка;
- страница ошибки авторизации;
- страница истёкшей сессии;
- страница технических работ, если она нужна инфраструктурно.

Ошибки должны быть оформлены в дизайне Arvexo и давать пользователю понятное действие: вернуться на dashboard, войти заново или обратиться в поддержку.

### 17.10 Минимальный набор страниц для первого релиза

Если нужно максимально сократить объём первого релиза, обязательный минимум страниц:

1. `/` — главная.
2. `/login` — вход через Arvexo Account.
3. `/auth/callback` — обработка входа.
4. `/onboarding` — выбор AI Track.
5. `/dashboard` — личный кабинет.
6. `/tracks/ai` — AI Track.
7. `/lessons/[lessonId]` — урок.
8. `/tournaments` — список турниров.
9. `/tournaments/[tournamentId]` — страница турнира.
10. `/tournaments/[tournamentId]/attempt` — прохождение турнира.
11. `/tournaments/[tournamentId]/result` — результат турнира.
12. `/admin` — админка.
13. `/admin/lessons` — управление уроками.
14. `/admin/tasks` — банк заданий.
15. `/admin/tournaments` — управление турнирами.
16. `/admin/tournaments/[tournamentId]/results` — результаты турнира.

Остальные страницы можно добавить в ближайшей итерации, если они не блокируют основной путь MVP.

### 17.11 Критерии готовности страниц MVP

Страницы MVP считаются готовыми, если:

1. Новый пользователь может войти через Arvexo Account.
2. Пользователь может выбрать AI Track.
3. Пользователь может открыть текущий урок.
4. Пользователь может выполнить задания урока.
5. Пользователь видит прогресс.
6. Пользователь видит приглашение на турнир.
7. Пользователь может зарегистрироваться на турнир.
8. Пользователь может начать и завершить попытку.
9. Пользователь видит результат после завершения турнира.
10. Администратор может создать урок, задание и турнир.
11. Администратор может посмотреть результаты турнира.
12. Все ключевые страницы оформлены в едином стиле Arvexo.
